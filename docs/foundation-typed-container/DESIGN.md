# Reader boundary and retained state

`QuerySourceSession.Operation.ReadTypedContainer` requires snapshot membership before constructing the internal reader. The explicit host-selected issuer attests the exact environment and original public/current private input mapping, owns the optional original origin, supplies the selected authority, and authenticates the issued container. Its resource check and the actual source/raw-operation leases are checked around provider access. The original public input's availability check also runs after its mapping is admitted. Input Source/Snapshot/Root and incoming handle Authority getters are not used to discover trust. This internal adapter is not a public plug-in factory or native acceptance mechanism.

The reader obtains governing type and IsList independently from the optional scalar fast path. True returns one validated cell without acquiring an enumerable; false ignores its out cell and consumes the ordered sequence. A scalar fast path can still represent a singleton list. Empty non-list and empty list containers stay distinct; neither implies nil or absence of typed value. Component handles are opaque: owned governing/declared/actual identities are retained, not reinterpreted as proof of union derivation. That semantic truth remains with the selected provider.

Every atomic cell must have separate provenance, owned declared/actual component handles, the expected optional original assessment, and a plain atomic payload. Default cells, sequences/maps/nodes/empty values and incoming evidence markers refuse. Integer/Decimal supplied coefficient/scale limits apply before normalization, independently from descriptive annotation strings. String bytes and aggregate memory have no new ceiling. The reader does not perform assessment, attach transport evidence, flatten the container into an XdmSequence or allow typed values into existing primitive numeric profiles.

The enumerated path grows storage from a small bounded initial capacity rather than the caller's maximum. It allows a final MoveNext to detect an extra member and refuses before reading that member's Current. Acquired enumerators are disposed exactly once under the raw lease, including when a getter revokes membership or cancels work. If cleanup also throws, primary and cleanup errors remain ordered via the existing preservation helper. Cleanup is attempted even after logical revocation; no retry or hidden disposal of borrowed providers occurs. A failure publishes no result and registers no evidence/cache entry, so a later valid read can succeed without stale capacity reservations.

A successful result is immutable retained metadata with guarded accessors. Container metadata, counts and atomic views recheck the originating operation, source, issuer, container and selected authority. Escaped views refuse after that raw operation completes. Returned component handles are still borrowed provider identities, and copied payloads are plain data: neither provides an authenticated VM transport or automatic resource retention outside the operation. Native/provider adapters must guarantee immutability or revoke/change their membership/version state before mutation; Core cannot infer that promise from an interface or hash.

This step deliberately does not activate public assessor binding, ReadTypedValue, ConstructSimpleValue, SchemaAtomics, compatibility or another host. It also does not choose persistent cache semantics. `MaxTypedValueAtoms` bounds this transient result; the public scalar-cache ceiling is not silently redefined as a container count. Typed numeric identity/computed-result provenance policy and later all-or-nothing marker/cache registration must be explicit before the public adapter is enabled. The public facade and all previous numeric descriptors remain unchanged.

Repeated raw membership checks use a direct reference loop instead of a capturing LINQ predicate. This preserves exact identity and liveness checks while eliminating repeated delegate/enumeration allocations. The original and refined binary cohorts are separated by SHA-256 pins and archived binding receipts, rather than identified by their shared engineering version alone.
