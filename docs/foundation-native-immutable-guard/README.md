# Private immutable provider output guard — TA-50

The large allocation problem is corrected **within the isolated native provider prototype**. Its output availability check no longer serializes a tree that is private and immutable behind `ProjectedNode` wrappers. It still checks cancellation and monotonic revocation on every call. The separate mutable request projection retains its complete serialization/mutation guard. No Core checks or production sources changed.

Fresh **59 carried adapter regression controls and ten separate-consumer controls pass**, with zero-warning/error builds. They cover poisoned foreign inputs, exact node/facts/origin ownership, request mutation refusal, root no-typed-value, invalid/unsupported results, cancellation, raw view expiry and separate result/session/admission disposal. The two lane counts describe carried controls, not a new complete native suite.

The identical ten-warmup/100-cycle pilot changes from about **31.5 GB to 149 KB allocated per cycle**, and median latency from **1,452 ms to 79.6 ms**. [Exact before/after](evidence/BEFORE-AFTER.json) preserves both metrics hashes. These are separate-process diagnostic observations on the same fixture/runtime/engine closure, not shipped-baseline or owner-budget acceptance. Zero output roots were observed alive after forced GC in both pilots; whole-process retained memory is not a per-object retention proof.

[The phase probe](evidence/PHASE-PROBE.json) now records 8,896 allocated bytes in public data evaluation, compared with about 31.506 GB before. This supports the causal correction: repeated serialization during the existing nested checks produced the churn. Residual callback CPU cost remains visible; no Core checks were removed or cached to improve it. The allocation blocker is resolved only for this exercised immutable-output profile.

The ownership argument is explicit: `Input` obtains its own clone from the native immutable assessment. Its `_document` is private. Navigation returns internal wrappers with read-only public methods, never an underlying XObject. String serialization exports a copy. `Input.Native` owns a different retained snapshot and its exports are copies. External consumers cannot call internal wrapping helpers or mutate their fields. Reflection and concurrent provider use are outside this serial prototype profile. This reasoning does not apply to `RequestInput`, whose exposed XDocumentNode requires the unchanged mutation guard.
