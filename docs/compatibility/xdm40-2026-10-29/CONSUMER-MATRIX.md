# Consumer compatibility and acceptance matrix

29 October 2026. Exact heads, clean-tree observations and file hashes are in [repositories.json](evidence/repositories.json). This is an inspection of real consumers, not a report of consumer builds against an implemented candidate. No production candidate exists for the revised proposal.

## XmlDb

The current XmlDb checkpoint includes M2 embedded recovery/process work, beyond the older M1 ADR. `PersistentXdmNode` still implements the XML-only `IXdmNode` contract. `ImmutableXmlSnapshot` now also carries commit sequence and reader/generation leases. Its documented single-evaluation-thread/no-concurrent-disposal rule remains explicit. The [existing consumer assessment](../../../../Bosal.XmlDb/docs/implementation/M2_XDM40_COMPATIBILITY_ASSESSMENT.md) is a separate 29 October review against an earlier core source head; it does not certify the present candidate.

| Boundary | Current real contract | Candidate requirement / migration | Acceptance still required |
|---|---|---|---|
| Source/API | `PersistentXdmNode : IXdmNode`; nested implementations of `IXdmSequence` and its enumerator. Exact Core `[1.26.2]` package reference. Storage/Core remain Bosak-independent. | Add optional interfaces/adapters; retain current required members and defaults. A plain persistent node need not implement a schema provider or generalized JSON node contract. | Compile actual Xdm/tests/sample against the candidate package, without altering original pins. Run complete provider/differential suites in an isolated copy. |
| Binary/value layout | Caller passes/returns `XdmValue` through `TypedValue`, axes, lazy sequences and VM results. | Prefer C44's existing-slot carrier; preserve assembly identity/signing compatibility as applicable. Any layout change needs a documented major-version migration. | Run unchanged binaries compiled against 1.26.2 with candidate dependencies, covering boxing, collections, sequence values and annotations. C44's synthetic replacement is insufficient. |

Do not persist JNodes as extra XML flags. ## Bosak.Schema

The add-on's package references are 1.26.3. Its explicit `SchemaCompileOptions.Version` already separates XSD 1.0/1.1. `SchemaAwareXslt.CreateCompiler` uses the existing `SchemaAware`/resolver surface, while the independent compiled-model/validation services use add-on-owned models and public Bosak evaluation/annotation APIs. Source inspection found no `IXdmNode` implementation in the add-on's `src`; typed assertion contexts are built with provider nodes/annotations.

| Boundary | Current real contract | Candidate requirement / migration | Acceptance still required |
|---|---|---|---|
| Existing integration | Existing `XmlSchemaSet`, compiler flags/resolvers, public annotations and package APIs are already consumed. ADR-006 is proposed, not adopted by core. | Preserve legacy unregistered behavior and signatures. Supply the neutral session through an add-on adapter; core references neither commercial assembly nor license services. | Actual add-on compilation and unchanged-binary substitution against the eventual core candidate; licensed/inert paths using existing owner-managed test arrangements. No activation/key work was performed here. |
| Component completeness | `ICompiledSchema` exposes assertions, alternatives, simple types and selected declaration/open-content/default-attribute data. `ElementDeclaration` records expanded element/type names and path, not C44's complete multi-affiliation/derivation graph. Validation source explicitly defers some full-component derivation checks. | Do not certify this model as a complete C44 session backend. Extend add-on component authority or explicitly refuse unsupported coverage. | Full claimed assessment, multi-head substitution/blocking, anonymous/list/union types, nilled/no-typed-value, actual type/declaration, defaults and error precedence. No partial-success result. |
| Closure identity | `SchemaCompiler.CompileCore` computes `Sha256Digest` from canonical root-document content before visiting the resolved closure; `SchemaId` uses its first 16 hex digits. | Retain existing public identifiers as legacy labels if needed; introduce a separate complete universe identity. Include all resolved bytes/origins, effective namespaces, include/import policy, XSD version, processor/profile and options. | Same root with changed imported bytes or base URI must not reuse authority/cache. Include chameleon schemas and conflicting redefine/override inputs. Root digest/QName equivalence must fail as a proof. |
| Compatible schemas | Current proposal's new identities are session-bound; independent compatible universes are unqualified. | Establish compatibility separately from issuer ownership. Same-session reuse is a fast route; validated handoff from compatible distinct universes must have an explicit proof/bridge path or a clearly limited supported profile. | Same component closure in distinct sessions; compatible strict supersets/subsets; conflicts; anonymous derivation; multi-stage transform/query handoff where revalidation differs. Retain original provenance and PSVI. |
| Atomic/node flow | Existing provider annotation helpers accept `IXmlSchemaInfo`; assertion contexts use private cloned XML views. | Keep the legacy projection, add a provenance-aware channel, and preserve actual governing types through atomization, function arguments/returns, copies and serialization. | Both same-valued/differently-owned types and same-QName/incompatible types; preserving versus stripping copies including descendants/attributes; primitive conversion policy. |
| Cache/concurrency/lifetime | Validation service uses a concurrent assertion-plan dictionary; the actual key is expression/default namespace/bindings. A concurrent dictionary does not certify model/session/provider thread safety. | Reuse current keys only where compilation is truly schema-independent. Any schema/profile-dependent plan adds the corresponding identities. Declare immutable session sharing, cancellation and retained value ownership explicitly. | Two schemas/profiles with equal expressions; concurrent independent assessments; provider faults/cancellation; use of values after the host releases its session reference. |

XDM's XSD 1.1 atomic definitions do not transfer full XSD 1.1 validation ownership into core. Keep REQ-139 and ADR-006 pending; this review is not acceptance of either the older typing-only callback or C44's 24-type surface.

## Braid

The effective development dependency is a verified clean source checkout at the 1.26.2 package source revision; the consumer separately records signed-package verification/adoption. Historical native acceptance remains scoped to its original conditional-authoring host. None of those receipts is relabeled as current-candidate acceptance.

## Compatibility disposition

**Source:** additive candidate appears feasible, subject to actual builds. **Binary:** unqualified for real consumers. **Persistence:** no migration required by the XML-only query scenario; future persistent typed/JSON values need separate design. **Behavior:** explicit profile/adoption gates are required because current-draft changes affect results without a source signature change. **Concurrency/lifetime:** preserve provider/host ownership and qualify the new session separately.

The proposed acceptance cases are requirements, not executed results. The review deliberately performed no sibling builds, package upgrades, product routes, storage writes, license operations or external notifications.
