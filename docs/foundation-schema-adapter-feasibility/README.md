# Native Schema public adapter feasibility — TA-45

The existing native assessment model can supply the bounded decimal/document facts needed by the public contracts, but it does not implement their issuance, input membership, environment binding or raw lifetime. A new provider adapter is required. No Core API addition is justified by this source review alone.

[Mapping](MAPPING.json) records ten concrete boundaries and [prototype controls](PROTOTYPE-CASES.json) define twelve required scenarios. These are a reviewed implementation proposal, not executed provider qualification or owner acceptance. [Exact source pins](ADOPTION.json) preserve the inspected inputs; [status](STATUS.json) states the remaining scope.

The native root retains its anonymous element-only type and no typed value. Present decimal children retain their real governing declaration and exact decimal value. Optional omissions create no nodes. Component identity comes from the retained assessor/component objects; schema text, names, paths and GUIDs cannot substitute for issuance.

The first isolated prototype must own an immutable input projection and authenticate the exact node/facts/input/origin tuple. Each advisor must issue its own origins, facts and complete typed containers. Assessment copies keep original component/assessment state while receiving fresh snapshot/node bindings. Decimal cells remain plain values with separate evidence; legacy private seals are not promoted. Invalid or unsupported assessment cannot expose a validated root.

Binding must preserve the exact engine-issued query environment without changing the native assertion grammar. Only an explicitly adopted strict document mode is proposed. Lax/type requests, construction, list/union/nil, persistent storage and compatible universes remain separate work. Borrowed views must obey the raw host operation; caller resources are never disposed by the adapter.
