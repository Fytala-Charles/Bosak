# REQ-140 — Owner return checklist

30 October 2026. This is a request format for already delegated owner work, **not** a recorded acceptance. Repository-local request IDs are namespaced below. Use a new dated response based on [the blank template](OWNER-RESPONSE.template.json), preserving its exact evidence inputs and any earlier receipts.

## Common return

- Name the owner role, actual consumer repository commit, candidate source/feed/package/assembly hashes and API manifest identity. Identify the supported profile and any exclusions.
- Map all known required foundation needs to exact existing/proposed public members and invariants. Return unresolved gaps explicitly; missing evidence is not an empty/accepted gap list.
- Execute actual consumer source/package and supported unchanged-binary replacement checks in isolated copies. Record commands, outputs, failures/refusals and baseline differences separately from new regressions.
- Cover positive/invalid/unsupported/error/copy and owner/resource/lifetime cases. Report cancellation, reentry and concurrency limits honestly; no general disposal/thread-safety promise follows from immutable metadata or a retained CLR reference.
- Return an explicit dated owner disposition (accept for an exact scope, defer or reject) and its evidence. A consumer qualification response does not unilaterally freeze Core or authorize package publication/product adoption.

A required unresolved contract need blocks shared freeze. Supported-profile exclusions must be reviewed; they cannot conceal a known missing foundation requirement for the full selected outcome. A passing build, synthetic provider or empty template does not supply the missing actual-consumer evidence.
