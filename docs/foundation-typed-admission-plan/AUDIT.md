# Typed-value trust and representation audit

The public contract is not an alias for `ISchemaIssuedScalar`. `ISchemaTypedValue` exposes a governing type and `IsList` independently from `TryGetSingleAtomic` and ordered `AtomicItems`; each `SchemaAtomicItem` contains a plain payload and separate declared/actual type and optional original assessment evidence. A true scalar fast path must not erase a singleton list's governing boundary. An empty result does not by itself identify a nilled node, no typed value, or an empty list. Original node facts retain nil/no-value separately. XDM atomization can project ordered atomics into a sequence after this context has been retained; it is not a reason to discard source/container metadata during admission.

The existing private association verifies its selected advisor's exact private environment, source availability, non-null original assessment and scalar/input/origin membership before guarded getters. Its cache is scalar-reference keyed and the kernel attaches evidence to one atomic XdmValue. It cannot directly represent the public list/container fast path. The underlying kernel permits a null scalar origin, but the association currently requires an original origin: originless construction needs its own explicitly authenticated route. No public `SchemaAtomics` implementation is activated by this audit.

The public `CompileXPath` currently refuses an assessor before Bind/getters. Original assessment/compatibility admission and `ReadTypedValue`/`ConstructSimpleValue` also refuse. These refusals are covered by poisoned-provider controls. Merely removing those guards would not establish a trusted public-to-private adapter. Binding must validate the exact engine-issued environment and selected assessor/advisor identities; ownership comes from that caller-selected endpoint's explicit membership checks, never from an incoming object's Authority property, name, digest, annotation string or interface implementation alone. Preserve the original public input reference alongside any private input projection for the public OwnsTypedValue predicate.

For each container read, raw session/snapshot membership precedes selected-issuer container checks, and both precede metadata, fast-path or enumeration getters. Validate governing/declared/actual component membership through the selected authority before using handle contents. Original origin, when present, must be owned and associated with the exact source/admission; copies can retain original source identity while current snapshot identity remains separate. Matching origin fields do not authorize a foreign input. Actual union member/type semantics remain provider-owned; opaque handle/name equality cannot prove derivation or membership. This is admission engineering, not a new XSD validation implementation.

Two policies must be resolved before public activation. `MaxTypedValueAtoms` explicitly bounds atoms consumed from one result, whereas `MaxCachedValuesPerSnapshot` currently describes issued scalar cache entries. A container count cannot silently replace scalar evidence accounting, and the product of the two limits is not an accepted memory budget. TA-01 therefore performs no persistent cache registration. A later decision must name both container and scalar-evidence accounting, rollback and refusal behavior. Do not preallocate from maxima.

Second, current finite numeric profiles reject all transport markers and derived/user annotations. They must keep doing so. A later explicitly identified typed profile needs an authorized numeric projection, preserved evidence on identity transport, deliberate rules for computed-result primitive type/origin, and rejection of foreign or revoked evidence. No string-name shortcut or unconditional marker stripping is authorized. Construction without original assessment is not identity transport or a new original validation episode.

TA-01 needs no demonstrated public signature change: its reader and retained container are internal. This does not prove all future public routing/signature needs are resolved. Public activation, schema facts/construction/compatibility, native adapters, actual owner performance and final API disposition remain later steps.
