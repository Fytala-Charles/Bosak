# Exact numeric constructor adoption — 4 November 2026

Recorded before source edits; base aa749240 / source 1.51.0. Adopt immutable [F&O REC-xpath-functions-31-20170321](https://www.w3.org/TR/2017/REC-xpath-functions-31-20170321/) section 18.1 (constructor function mapping), 19.1.2.3 (numeric decimal conversion) and 19.1.2.4 (numeric integer conversion), preserving prior arithmetic/division/representation adoption. No later draft/erratum adopted.

Implement only one outer xs:integer(...) or xs:decimal(...) around the existing finite numeric grammar, optionally inside the existing top-level string/fn:string wrapper. Only standard-bound xs prefix is admitted; no arbitrary aliases, nested constructors, cast-as/castable grammar, strings, untypedAtomic, floating/Boolean/derived/schema inputs or user types. Integer conversion discards the fractional part toward zero; this is the specified numeric conversion, not rounded decimal division or an inexact legacy accessor fallback. Decimal conversion preserves exact value and changes primitive kind. The constructor creates plain XDM numeric data, not authenticated schema evidence, assessment, facets or provenance.

Supplied and intermediate quotas apply before conversion, even where truncation would shrink an invalid input. For integer conversion, compare actual coefficient decimal digit count against scale before creating a divisor: a sufficiently tiny value returns zero, and any necessary power of ten is bounded by admitted coefficient width. Preserve raw availability checks and original close/cancel/release/drain obligations; no total-memory/time budget inferred.
