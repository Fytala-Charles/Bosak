# Bounded primitive numeric constructors

Use the existing `SchemaQuerySession.CompileXPath` overload with explicit `SchemaQueryLimits`. One outer `xs:integer(...)` or `xs:decimal(...)` selects `bosak-exact-constructors-v5` / `bosak-exact-constructors-static-v5`. Its descriptor binds `constructorPolicy=primitive-numeric-v1`, `integerConversion=truncate-toward-zero`, retained exact-terminating division policy/algorithm and captured numeric/output limits. Existing expressions without these wrappers retain their prior profiles and fingerprints.

Examples: `xs:integer(-3.99)` returns Integer -3; `xs:integer(-.99)` returns Integer zero; `xs:decimal(123)` returns Decimal 123; `xs:integer(9 div 2)` returns Integer 4. The body supports the existing finite numeric literals/unprefixed variables/arithmetic grammar. The existing outer string wrapper also accepts `string(xs:integer(3.99))` and correctly bound `fn:string(xs:decimal(123))`. Conversions follow [F&O dated Recommendation](https://www.w3.org/TR/2017/REC-xpath-functions-31-20170321/), sections 18.1, 19.1.2.3 and 19.1.2.4, restricted to admitted primitive integer/decimal inputs.

Only the standard-bound `xs` prefix is admitted. An explicit different binding refuses compilation; captured namespace changes cannot alter a compiled session. Arbitrary prefix aliases, unprefixed constructor names, nested constructors, constructors inside arithmetic/comparisons, cast-as/castable syntax, string/untypedAtomic/floating/Boolean inputs, empty/sequential arguments and derived/user/schema types remain unsupported. Comparison results cannot feed a numeric constructor. This is not general XPath casting or schema simple-value construction.

Supplied coefficient/scale and all arithmetic intermediate limits apply before conversion, even if truncation would produce a small result. For integer conversion, actual coefficient digit count is compared with scale first: tiny values return zero without a scale-sized divisor. Any remaining power of ten is bounded by actual admitted coefficient width. Decimal conversion preserves value and changes primitive kind. No rounded or floating fallback occurs; `xs:integer(1 div 3)` still refuses because the intermediate division is nonterminating. Existing output bounds and checked legacy narrowing remain active.

Results are plain XDM numerics. Naming an XSD built-in constructor does not issue schema evidence, authenticate annotation strings, perform assessment/facet validation or enable `ReadTypedValue`/`ConstructSimpleValue`. Incoming issued/derived/user-annotated values retain their existing admission refusals. Use exact accessors for wide results. Session close/cancellation, raw lease completion, release and drain retain existing obligations; no hard CPU/aggregate-memory guarantee is added.

See [qualification](README.md), [finite adoption/deviations](SPEC-BASIS.md) and the [earlier division guide](../foundation-exact-division/GUIDE.md). Typed/schema/native/all-host and freeze/publication acceptance remain separate work.
