# Pinned standalone W3C XSLT 3.0 reference qualification

12 November 2026. **The catalog attempt completed, but qualification is unsuccessful: 22 cases failed.** This is a measured reference result, not a new required gate or baseline adoption. Existing engine code, harness policy, assertions, skip lists and frozen QT3/qt4 gates are unchanged.

## Observed result

| Scope | Passed | Failed | Skipped | Not run | Missing test sets |
|---|---:|---:|---:|---:|---:|
| Entire original 234-set / 14,601-case catalog, basic profile | 10,199 | 22 | 4,380 | 0 | 0 |

All original cases are accounted for. There was no set/case filter, resume file, retry, assertion correction, or skip admission. The **870.282-second** attempt finished within the 1,200-second wall limit and 8 GiB Windows job-memory envelope. Those limits are diagnostic stop conditions, not accepted performance budgets. No timeout or partial run is hidden in the counts.

The unchanged legacy runner returned **exit code 0 despite 22 failures**. The external controller parsed the complete summary and correctly recorded `success=false`, returning 1. Exit zero alone must not be treated as a conformance pass. The runner's printed percentage excludes skips; the table above intentionally reports explicit counts instead.

**Corpus-write limitation:** execution changed four tracked resources inside the disposable clean-start corpus, including an expected-output file, and created 250 additional files. All changed/generated bytes are retained. This needs write-isolation review before gate adoption; recorded passes are not a claim of an immutable corpus throughout execution. Every one of the 234 test-set definition files retained its pre-run hash. The original edited corpus was not used for execution, reset or cleaned: its **13,229 inventoried tracked and untracked files** remain byte-identical to their pre-run inventory.

## Integrity and retained evidence

The disposable corpus changed these tracked paths during execution:

- `tests/misc/xslt-compat/xslt-compat-003-2.out`
- `tests/strm/si-for-each-group/account01826370.xml`
- `tests/strm/si-for-each-group/account43861562.xml`
- `tests/strm/si-for-each-group/account92741838.xml`

The original edited checkout's inventoried file set and the launched runtime layout both compare equal before/after. The disposable corpus is retained with its generated files; no restore/reset/cleanup was used to conceal writes.

A [read-only path review](WRITE-ALIAS-REVIEW.json) identifies an assertion-independence issue in `xslt-compat-003`: the secondary-result URI and nested `assert-xml/@file` use the same name, and the pinned adapter resolves both to `xslt-compat-003-2.out` under the test-set directory. The produced document therefore overwrites the file-based expected document. This case was reported as passed. Its before/after parsed XML trees are equal in this observation (the changed bytes are serialization layout), so this review does **not** establish that an incorrect result was accepted. It does establish a path collision that needs a separate fix/refusal control before gate adoption.
