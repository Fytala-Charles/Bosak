# Exact terminating decimal division

Use the existing `SchemaQuerySession.CompileXPath` overload with explicit `SchemaQueryLimits`. Expressions containing `div` select `bosak-exact-division-v4`; its descriptor `bosak-exact-division-static-v4` binds `divisionPolicy=exact-terminating`, `divisionAlgorithm=gcd-factor-chunks-v1`, numeric limits and derived output capacity. Expressions without `div` retain their previous profile selection and descriptors.

Examples are `1 div 8` (Decimal 0.125), `6 div 3` (Decimal 2), `3 div 6` (Decimal 0.5), `string(1.20 div .03)` (String 40), and `1 div 2 eq .5` (Boolean true). Division shares multiplication/idiv/mod precedence and associates left. Unary signs bind first. Integer operands still produce a Decimal result. Use `ExactDecimalValue` for full result access; legacy decimal narrowing remains checked. This does not admit arbitrary nested functions or Boolean arithmetic.

Supplied values must satisfy primitive integer/decimal admission and coefficient/scale bounds before arithmetic. The implementation reduces coefficient GCD, checks whether the reduced denominator contains only factors 2 and 5, and cancels those factors against wide scale arithmetic before result growth. It removes/grows factors in bounded chunks, preflighting multiplication before constructing a result coefficient. Extreme scale differences never cause unchecked powers or padding; a huge caller ceiling alone does not cause a huge guard threshold. Individual BigInteger primitives still have no hard time or immediate-cancellation guarantee.

Nonterminating results such as `1 div 3` raise `NotSupportedException` during evaluation. They never produce rounded or floating values. A result that exceeds digit or scale capacity also refuses; for example `1 div 32` needs coefficient 3125 and scale 5. Zero divisors, including zero divided by zero, raise `DivideByZeroException` carrying FOAR0001 after supplied-input admission. These are scoped host mappings; complete standardized error-graph integration is pending. Sessions remain reusable after arithmetic errors and cancellation. Close revokes raw use while retaining owned resources until completion; drain then confirms deferred release.

Earlier [arithmetic](../foundation-bounded-numeric/GUIDE.md), [comparisons/map keys/string bounds](../foundation-exact-scalars/GUIDE.md) and [idiv/mod](../foundation-exact-quotient/GUIDE.md) behavior remains available. Bare ordinary `string($x)` retains ordinary-profile admission; an arithmetic body selects the numeric profiles. No rounding-mode API, float query arithmetic, typed/schema numeric operations, general serializers or wider host integration is introduced. General legacy XPath/XQuery/XSLT routes retain their behavior. The earlier typed-default overload migration still applies; final release acceptance and API freeze remain pending.
