# Structured internal completion prerequisite

The reviewed owned XSLT run result must retain admission, work and cleanup failures separately. This step connects the TA-29 lease-acquisition report to an internal source RunOutcome, and adds a shared structured completion path to the provider/host operation scope. No public API is activated.

Source membership preparation remains shared with ordinary Run/RunAsync. The structured run acquires the actual raw session/source leases, captures admission failures and reverse rollback errors, executes the callback, checks the final raw lifetime and waits for actual completion. A returned null is distinguished from no result. A produced value remains in the internal report when the final guard detects cancellation or revocation; IsSuccess requires a result with no admission/work/cleanup error. Results remain borrowed unless a future host layer explicitly detaches them.

Completion closes admission to new work immediately, waits for the current provider or host call to exit, releases target then source provider admissions, and then releases raw leases. Its shared task contains an immutable cleanup array and the first request's original primary error. Repeated completion uses that same task and never retries callbacks. Provider aggregates and repeated exception objects are retained as supplied. An exception thrown by the raw release callback is one cleanup item. The throwing CompleteAsync adapter reproduces original-error or primary-first aggregation; legacy Run/RunAsync continue using that adapter. The throwing task remains shared and faulted (rather than canceled) for an OperationCanceledException, while report-only observers do not create a hidden faulted task.

AdmissionError refers to raw source admission. WorkError refers to the callback or final guard. A provider call's own aggregate, including its acquisition/rollback failure, remains one original work exception; this layer does not flatten it or guess its internal provenance. Errors on detached tasks are not collected. There is no new general concurrent/reentrant provider guarantee, observer cancellation token or early-release shortcut.

Sixteen new cases include successful null results, invalid membership, pre/final cancellation, admission rollback failures, nested work errors, real source closures and reverse release ordering, provider cleanup failure, repeated structured/throwing observers, raw callback failure and an exclusive file held by a blocked actual host call through a canceled wait. Existing admission, host and provider lifetime tests remain in the full suite. Representative owner allocation/latency/memory budgets and arbitrary schedules remain unqualified.

Copied bounded capture options, actual serializer ownership, inherited control gates, fresh per-run resource receipts and original execution-error diagnostics must be qualified before AH-03 closes. The eight-library XQuery preview closure remains selected until a public XSLT checkpoint exists; no package artifacts or release date/version are selected.
