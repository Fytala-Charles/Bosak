# Exact internal host outcome routing

The TA-30 runtime report now connects to the API captured-host session without exposing a general public callback factory or changing ordinary Run/RunAsync. SchemaQuerySession.RunHostOutcome checks both binding identity and that the binding owns this exact session. A second internal session created with the same binding cannot mint executable ownership. CapturedHostBinding.RunOutcome also checks the actual executable reference before any provider/source callback.

Malformed membership, closed sessions and pre-cancellation become admission reports before producer execution. Runtime source admission still validates complete immutable membership. The API callback receives an operation stamped with the exact host. Existing frame/role/root/context/ownership checks remain mandatory for host execution. After actual cleanup, the API checks only engine session and snapshot lifetime, without reentering provider availability/getter callbacks. A new delivery refusal becomes WorkError only when there is no existing admission/work error; original errors are never flattened or overwritten, and cleanup errors retain their original order/category.

The internal class-only route supplies a one-use stage callback for an already-produced diagnostic object. It accepts a non-null object during the producer callback and closes when that callback returns or throws. Normal return closes staging atomically with identity checking; a returned staged result must be the same object. Repeated/null staging and mismatched return refuse. An escaped callback cannot mutate a completed report. If final frame/raw guards throw after staging, the report retains the staged object and original errors while IsSuccess stays false.

Staging is trusted engine plumbing, not proof of detachment. It copies no graph, grants no authority, and does not make borrowed results safe after completion. The future serializer/capture implementation must stage actual detached capture data before final host checks. This step does not activate public XSLT types, copied capture options, serializer/control gates, or a public owned outcome.

Twenty-three new cases cover exact identity, invalid membership, admission revocation, staged diagnostics under four revocation sources, staging lifetime/identity, original work and duplicate aggregate cleanup identities, post-cleanup closure, cleanup-only errors, no fabricated result and actual file-backed host-tail retention through canceled observation. Existing host, source and completion controls remain in the complete suite. Native concurrency, worker ownership and representative owner performance budgets remain separate qualifications.

The first build caught six generic-inference errors in the new test calls; explicit object type arguments correct them. That failed receipt is retained. Qualified build and focused/full tests are the final evidence. No managed negative case was launched unhandled. Package metadata remains the exact eight-library XQuery closure; no package artifact or publication date/version is selected.
