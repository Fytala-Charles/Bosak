# Isolated capture feasibility basis

Recorded 1 November 2026 before candidate changes. Production source pin: d322360b. Inherit immutable XSLT 3.0 Recommendation REC-xslt-30-20170608, sections 2.3.2–2.3.4, 3.5.6 and 10.1.1, as adopted in [explicit-context basis](../foundation-xslt-context-promotion/SPEC-BASIS.md). Output serialization and result-document/message behavior reuse the existing 1.42.0 capture implementation rather than introduce a language-semantic change. This candidate changes host ownership/composition policy in an isolated source copy only.

Intentional bounded profile: document-root initial match, separately supplied global document, source-free named template; no arbitrary initial sequences, streaming, external modules or schema-aware compilation. Reuse existing supported bounded serializer profiles and cooperative controls; no memory/compile-time sandbox. Closed-resource policy reports actual Unsupported routes and performs no external acquisition. Existing input capture refuses caller resource policies and execution gates rather than silently weakening them. Public gate composition and arbitrary authorized resources remain unsupported and must be reviewed explicitly before promotion. Trusted synthetic membership predicates do not establish native Schema/XmlDb authority. No production implementation or specification adoption is promoted by this experiment.
