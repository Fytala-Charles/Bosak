# C44 — Bounded production implementation plan

**Proposed, pending owner acceptance.** No step below is implemented or released by C44. Version 1.33.1 remains unpublished; any eventual additive feature candidate needs the normal minor-version decision during implementation, not a C44 bump.

1. **C45 guarded core candidate.** Implement the reviewed neutral contracts and strict result/identity validation in Core; optional node annotations and the existing-reference-slot atomic channel; compile-time session capture in API/XQuery/XSLT and clone propagation. Preserve all current XmlSchemaSet/stream/QName APIs. Any owned schema operation not yet connected to the session must refuse with explicit unsupported coverage before legacy type-name/component interpretation. Do not expose an attachable identity carrier that can silently flow into unwired legacy schema checks. Raw value access, standard atomization/binding/conversion and copied metadata need end-to-end tests, not just the isolated carrier checks.
2. **Qualify C45 before merge/API freeze.** Precompile real consumer programs against the unchanged core, run them against the candidate, audit public signatures/managed layout and every reference-payload accessor, and exercise all atomic families, sequence/array/map transport, numeric equality/hash keys, serialization, EBV, date/time/timezone, QName/NOTATION and explicit casts. Test same-name foreign sessions, cancellation/fault/diagnostic handling, source preservation, strip/preserve, disposal and concurrent execution. Measure actual no-session allocations/performance. Require fresh full solution tests and exact normal gates **31,397/0/424** and **8,941/0/1,918**, all skip names/reasons and 230 qt4 sets unchanged.
3. **C46 component/assessment dispatch.** Complete provider-owned static visibility, schema imports, type constructors/derivation, actual member sets, function subtyping, validating constructors and source loading. Preserve legacy-only paths; forbid owned unsupported downgrade. Give XPath/XQuery/XSLT adapters their existing precise error precedence. A deterministic fake provider can prove routing; it cannot certify the commercial component model or original XSD 1.1 assertions.
4. **Separate add-on readiness.** Bosak.Schema owns its affiliation lists, complete complex derivation, assertion inheritance/CTA/xsi:type interaction, immutable closure identity and structural validation coverage. The C43 source findings remain open until qualified by that owner. No sibling modification, activation or commercial source reuse is authorized by this core plan.
5. **Licensed integration and admission.** Use an explicit separate integration runner against published core/provider packages with normal core gates independent of the add-on. Re-execute the six original QT3 multi-affiliation assertions, 30 documented XSLT cases and separate validation-1301 CTA witness, keeping catalog-005b's independent applicability constraint. Preserve original queries, assertions, resources and diagnostics. Any skip/baseline change and any release requires its own concrete qualification and owner approval; none follows automatically from contract acceptance.

API freeze requires exact implemented-shape review and the production checks above. Contract-direction approval authorizes a bounded candidate, not an immediate permanent compatibility claim, provider certification, conformance admission or publication. REQ-139 stays Pending until its real acceptance criteria are fulfilled; REQ-126 bounded closure and all historical observations stay intact.
