# K02: duration-schema boundary and import diagnostics

**27 October 2026 — unpublished source candidate 1.26.5; public 1.26.3 unchanged.**

`validateexpr-28` imports a schema that restricts `xs:dayTimeDuration` and `xs:yearMonthDuration`. The current .NET schema compiler rejects those names in schema definitions before the QT3 query executes. This remains a loader/profile boundary. Substituting `xs:duration` would require independent proof of subtype, lexical, facet and typed-value behavior; this slice makes no such substitution.

There is also a separate, bounded public error-contract defect. Passing the original query and original schema through `XQueryContext.WithSchemaResolver` reaches `XQueryExecutable.BuildSchemaSet`; collected compilation errors previously escaped as an unclassified `InvalidOperationException` beginning `Schema compilation failed`. That diagnostic now starts with **XQST0012**, retaining every collected detail and the existing evaluation phase. This follows [the dated XQuery 3.1 Recommendation, section 4.11](https://www.w3.org/TR/2017/REC-xquery-31-20170321/#id-schema-import). The [adoption record](ADOPTION.json) was written before implementation. The schema datatype definitions are separately documented in [XSD 1.1 Part 2](https://www.w3.org/TR/2012/REC-xmlschema11-2-20120405/#dayTimeDuration).

Nine [public API regressions](../../../tests/Bosak.XQuery.Tests/SchemaImportErrorTests.cs) cover both unavailable duration base names, another missing type, an invalid numeric facet, valid string/duration schemas, missing resolution, resolver I/O and malformed XML. Before correction: 4 failed/5 passed. Afterwards: 9 passed. Missing schema lookup remains XQST0059; resolver I/O and XML parser failures are preserved. This correction covers only the existing aggregated compilation diagnostic, not every schema-reading exception or complete eager static validation.

The original QT3 assertion accepts either the expected XML result or XQST0012. The independent public-resolver probe now reaches the error alternative. That is **not a normal-runner pass**: the harness still precompiles the environment schema and raises the same `XmlSchemaException` before the query pipeline. Both direct executor observations are preserved, as are the original query/schema hashes and original assertion. No skip removal, exception-to-pass shortcut, fixture change or schema shim is introduced.

The six multi-affiliation substitution-group cases remain separate capability work. K02 remains open for the actual loader/profile boundary; this slice completes only the bounded public diagnostic correction. Current frozen requirements remain QT3 **31,144/0/677** and qt4 **8,436/0/1,894**. REQ-126 bounded acceptance and all original unmet observations remain unchanged.

Recommended next slice: design deferred query-owned schema loading and explicit supported-profile diagnostics, with independent schema-source/validation tests. Do not turn arbitrary environment exceptions into accepted query errors. Any later admission change requires its own evidence and baseline-policy approval. Full XSD 1.1 duration semantics and the six substitution cases should not be conflated with error-code classification.
