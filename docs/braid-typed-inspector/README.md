## Lifetime finding

The diagnostic requests context unload and its own lease then refuses access. Holding the actual raw port and target nevertheless permits a real same-name NoChange call afterward: the exact same target instance is returned, with no candidate and no failure. Retained source bytes remain unchanged.

This is expected CLR/reference behavior, not proof of unload/GC completion or a bug in the currently pinned product (which has no such session integration). It demonstrates that **unload requests and an outer inspector gate do not revoke escaped ports**. The current diagnostic lease is not a production proxy: the actual result still exposes raw ports. Every exported port/target would need session-bound admission or explicit refusal/removal under an honest operation profile before a product guard could claim lifecycle enforcement. Inspection success cannot be taken as that proof.

## Receipt corrections and limits

The initial host build lacked PE-reader imports/internal helper access and had an unproved nullable-port use; the initial compiler log is retained. An initial positive target fixture used a module include, and the real adapter correctly refused it with UnsupportedModule. That original failure/diagnosis is preserved; the final proof keeps the refusal check and uses a dependency-free fixture for positive ownership/NoChange checks. No product restriction was relaxed and no production source fixed those harness issues.

The proof exercises actual unchanged adapter binaries with the current Braid 1.26.2 engine pin. It does not upgrade to 1.34.1, migrate Desktop composition, implement a complete guarded facade, edit/apply source, integrate preview/export/real product-worker transport, migrate history, certify parallel/in-flight closure or callbacks/reentrancy, prove unloading, or establish native UI/accessibility acceptance. The separate direct baseline process intentionally loads the adapter normally; the isolated host's default-context absence check is therefore uncontaminated. Shared contract metadata/hash approval and private-layout rejection are diagnostic admission rules, not a new product API.

All original consumer, engine and Schema source/pins remain unchanged. Earlier model/runtime/source/binary and full engine/Schema qualifications are inherited, not rerun. All prior sealed dossiers remain intact.
