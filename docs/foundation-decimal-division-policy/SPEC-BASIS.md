# Decimal division policy adoption basis — 4 November 2026

Recorded before the reference experiment; Core base f9e7c615, source 1.50.0. Immutable sources: [XPath REC-xpath-31-20170321](https://www.w3.org/TR/2017/REC-xpath-31-20170321/), section 3.5 (arithmetic precedence), and [F&O REC-xpath-functions-31-20170321](https://www.w3.org/TR/2017/REC-xpath-functions-31-20170321/), sections 4.2 and 4.2.4 (numeric division, decimal result for integer inputs and zero-divisor error). No later draft or erratum is adopted. Preserve the prior XSD decimal representation adoption. Local scope inputs are pinned by file hashes and base revision in INPUTS.json.

This step selects a bounded implementation policy, not a production semantic adoption or owner acceptance. Next implementation: exact terminating primitive integer/decimal division only; no rounded or floating fallback. An irreducible denominator containing factors other than 2 or 5 refuses as unsupported. This is intentionally narrower than general XPath decimal div, whose complete precision/rounding and error policy remains unresolved for wider host qualification. Do not treat nontermination refusal as an XPath-mandated result or label this subset full conformance. Existing legacy division is unchanged.

No production source, signatures, version, packages, owner pins or historical receipts change. The independent Python reference experiment validates mathematics and bounded coefficient construction only; it does not exercise C# BigInteger, public sessions, cancellation races, retained memory or real consumer performance. Runtime qualification and full gates are required for the subsequent implementation, with specification scope recorded again before source edits.
