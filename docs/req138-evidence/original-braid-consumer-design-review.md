## Consumer decisions

| Design area | Consumer assessment |
|---|---|
| Coordinated delivery | Accept Wrap/Edit condition/Unwrap together: the two structural operations plus the necessary additive bridge belong in one engine implementation PR, then one consumer integration PR after signed publication. No arbitrary wrapping or whole-subtree Delete substitution. |
| Initial profile | Accept one no-namespace literal E under a supported top-level template or literal-only ancestry; independent Unwrap discovery removes precisely one approved if edge when checking hypothetical eligibility. Existing ancestry predicates must not be relaxed globally. |
| Prefix/static context | Accept deterministic ordinal selection of an existing nonempty XSLT prefix in the parent's insertion context. E-only declarations cannot authorize a wrapper prefix; no new declarations/rebinding/default changes. Compile the condition in actual candidate I/test context inherited from P, preserving expanded text through escaping/normalization. |
| Exact structural edits | Accept exactly two same-original edits: Wrap inserts O/X; Unwrap removes only O/X while retaining C. Complete old/new payloads, sorted/simultaneous or descending replay and component-aware endpoint ownership are explicit. The selected E endpoint at b and suffix start at b intentionally translate differently. |
| Complete graph proof | Created wrapper/test versus removed wrapper/test partitions exhaust ordinary inspection alongside all mapped nodes/attributes/merges. Only approved parent/depth edges change; internal subtree order, metadata/raw bytes and outside nodes remain proved. Selection follows actual new I or retained E using fresh inspection identities. |
| Both Unwrap boundaries | Accept support for up to two distinct groups, each with two actual ordered original fragments, disjoint survivor/merge partitions and exact candidate ranges/bytes. E separates the groups; a single-group deletion verifier is insufficient. |
| Narrow lexical whitespace | Accept the explicit first-profile restriction to plain lexical space/tab/CR/LF at optional inner/adjoining outer boundaries. Character/entity-reference boundary text refuses; entity spelling inside retained E remains intact. This is a reviewed narrowing, not implicit general text normalization. |
| CR/LF seam | Accept recomputing normalized candidate logical text from complete concatenated raw fragments. A trailing CR plus leading LF normalizes once; concatenating independently normalized original Text values would be wrong. Require seam bytes, fragment/whole ranges and actual inspection coordinates over all four encodings in implementation tests. |
| Existing editor bridge | Accept additive ProposeExpressionEdit(proposal, token), independently advertised bounded capability/profile and limits, legacy one-argument/binary behavior unchanged and no ambiguous default argument. Append refusal enum values without renumbering. Reuse validation/emission rather than create another condition editor. |
| Expression proof/NoChange | The bounded overload must prove complete original/candidate node/per-owner-attribute correspondence with only the owned test value changed, validate both modules under its restricted profile and deny ambient acquisition. Braid independently verifies source/slot/correspondence before complete-byte equality feedback. Equal bytes grant no Apply/port adoption/history/redo loss; equal output or equivalent XPath does not suffice. |
| Limits/cancellation | Accept independent8 MiB source,65,536-code-unit condition,1 MiB escaped condition, bounded prefix/markup,65,536 nodes/attributes/depth256 and32 MiB cumulative evidence budgets. Candidate depth and encoded output must be pre-counted. Tokens cover bounded phases and immediately before return; opaque compiler phases have cooperative boundaries rather than a hard preemption guarantee. Unexpected defects remain defects. |
| Consumer gates | Complete review, unconditional-content acknowledgement, source/intent/slot/operation/license/currentness/overlap checks, separate atomic Apply, committed-late-cancellation success, one-step history, fresh I/E selection and historical validation/preview/export evidence match IF01-IF15. |

No design correction is requested. The proposed prefix policy, plain lexical boundary narrowing, two-merge handling, additive existing-editor overload and complete-evidence budgets are confirmed from the Braid consumer perspective. Implementation must demonstrate them; this review does not certify code that does not yet exist.
