Please assess these concrete proposed choices:

1. Separate SupportsTextDeletion capability, opaque owned target and proposal, and operation-specific two-way complete Candidate/Failure. No caller ranges/payload/layout; no reuse or broadening of value-of authority. Empty/self-closing deletion still changes source and has no NoChange result.
2. Accept paired empty, paired ordinary nonempty and self-closing literal text, proving retained syntax/context. Self-closing has null OriginalBodyRange, paired empty has its real empty span. Effective non-expansion and no output escaping; exclude CDATA/comments/PIs/elements/ambiguous body forms even where Kind=Text appears plausible.
3. Preserve REQ-130's initial parent scope: no significant direct parent text/direct CDATA or surviving ancestor preserve, even with nearer default reset. Supported xml:space on the removed instruction alone belongs to its removal metadata. These are deliberate deletion limits; accepted replacement preserved/mixed behavior remains unchanged.
4. Exactly one full instruction edit and zero-byte candidate seam, every outside byte unchanged, including unused namespaces/blank indentation. No tag regeneration, cleanup, output-equivalence requirement or synthetic node. Actual mapped surviving parent is the resulting selection.
5. RemovedNodes includes the actual instruction plus actual payload when present (one or two descriptors). O partitions into R/map-domain/merge-originals and C into map-image/actual merge destinations. No payload survivor or one-removed-node assumption.
6. Zero/one reviewed REQ-130-style two-fragment ordinary whitespace merge, complete contiguous byte coverage and actual destination. XML parsing of the joined run remains engine-owned; original parsed Text concatenation cannot establish CR/LF/reference semantics. No unproved/general mixed merge or parallel Braid XML parser.
7. Independent original/final 8,388,608 physical byte bounds, strict four encoding variants, captured static/resource validation before emission and no repair of invalid originals. Cooperative new typed Cancelled refusals at discovery/proposal preserve legacy value-of cancellation semantics unchanged.
8. Replacement-independent text-deletion adapter validates complete removal/map/merge/source evidence and current session/license/revision, frozen review, explicit atomic Apply/history/parent focus and late cancellation. Source/package/public delivery and real worker/export/reopen/native acceptance are separate gates.

Include or link Braid's dedicated text-deletion operation design/ADR; no consumer ADR identifier is assigned here. Independent baseline probes should use public APIs and ordinary descriptor traversal; baseline parser shapes do not implement deletion. A no-blocking design review authorizes neither engine implementation nor release/native acceptance. Implementation requires subsequent user authorization.
