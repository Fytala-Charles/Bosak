# Exact calendar comparison contract

25 November 2026. Twenty related contracts are grouped into one additive comparison batch, with implementation, commit/push, review and automatic passing merge. Immutable normative sources and intentional bounds are recorded in [ADOPTION.json](ADOPTION.json) before implementation. No publication.

Provide explicit CompareXPath(left,right,implicitTimezoneMinutes) with a validated mandatory offset from -840 through840, and CompareXsd(left,right) returning Less/Equal/Greater/Indeterminate. DateTime and dateTimeStamp share a comparison family; time is separate. Reject default or incompatible comparison operands. XPath uses the supplied implicit timezone only for absent offsets. XSD two-absent values compare locally; a mixed pair compares only if both extrema of the absent value's +/-14-hour interval give the same strict direction. Equality at just one endpoint remains indeterminate.

Use exact BigInteger Gregorian timeline arithmetic and normalized decimal seconds, including year zero, negative/extended years and fractions beyond DTO/millisecond resolution. Use a shared1972-12-31 reference date for time; retain day displacement after timezone normalization. No modulo-day equality. Internal timeline coefficients stay within a fixed320-digit bound for the already bounded input model.

Provide SameKey/GetSameKeyHashCode plus an explicit CLR IEqualityComparer for exact calendar objects. Same-key requires matching primitive families and matching timezone presence; aware operands compare on the UTC timeline, absent operands on the common local timeline. DateTimeStamp is derived from dateTime. Hashes use the same normalized exact timeline/family/presence and are process-local. Default values refuse; valid incompatible families returnfalse. Ordinary component equality, private marker binding and original authority remain unchanged even when values compare equal.

Do not lift the existing XdmValue map guard or change normal expression operators. The old comparer uses legacy millisecond/embedded-date keys; mixed exact/legacy interoperability and default-engine semantics need their own adoption and qualification. New APIs operate on explicit exact value objects, without creating or transferring schema authority. Native Schema datatypes/facets, arithmetic, UTC canonicalization and C45 acceptance remain separate.
