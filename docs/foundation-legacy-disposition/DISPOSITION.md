# Keep legacy admission and public authority distinct

The legacy SchemaEvidenceKernel accepts opaque object type/assessment fields under ISchemaEvidenceIssuer, a private seal and a private snapshot. QuerySchemaAssociation additionally verifies its exact input/origin and registrations. Those checks remain intact. They do not automatically establish the public advisor/authority/input/origin/environment relation, even when an object implements a public interface.

SchemaAtomics still refuses legacy Evidence markers before their fields are consulted. The sealed private marker does not implement the trusted engine public-observation interface. Public complete readers first authenticate exact provider container issuance and then reject marked values where plain cells are required. No cast, marker promotion, public attachment/strip factory or new automatic adapter is selected. Existing private scalar/session/cache/quota/lifetime/cleanup behavior is preserved.

For public typed migration, re-obtain a provider-issued complete container under the actual public advisor/authority and admitted source. Use the matching public snapshot and raw callback with ReadTypedContainer or eligible ReadTypedValue. A provider may reissue authentic existing assessment state; copied fields do not invent historical origin or perform validation. A locally assembled wrapper must still be owned by that provider. Explicit copying to plain data is declassification, not migration of authority or authenticated identity.

Private scalar evidence cannot reconstruct absent empty/list/union/nilled/no-typed-value boundaries. Supply actual complete source facts or explicitly refuse unsupported coverage. Public compatible work still requires its own exact raw paired proof. Private seals and expired views cannot revive or become public admissions. New direct bridge needs require an actual owner case, immutable adoption, complete ownership/source/lifetime/limits/rollback/proof/cleanup design and fresh public/native/binary/gate/budget qualification.

PV-L01 is CompleteWithScope for the Core disposition only. It does not close PV-01/R3, actual native migration, C45, API freeze or publication. Next PV-Q01 audits exact-candidate provider/performance qualification gaps. [Immutable XDM basis](https://www.w3.org/TR/2017/REC-xpath-datamodel-31-20170321/) and exact source hashes are in ADOPTION.json; the authority and migration rules are explicit Bosak host policy.
