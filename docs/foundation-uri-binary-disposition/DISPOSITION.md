# Retain the existing public representation

Use the existing annotated String carriers for anyURI, hexBinary and base64Binary, together with separate provider-owned governing/declared/selected types and original assessment metadata. Both qualified complete-container profiles preserve those strings and tags without inventing a new native byte buffer or resource lease. This is Core selection of the present representation, not owner/native or full value-space acceptance.

The pinned anyURI/base64/hex cast routes and URI function producers return FromString with type tags. Constructors may validate/normalize before returning; complete-container transport does not repeat that conversion. FromString with a type tag alone is not an independent validation operation. No new FromUri/FromBinary/byte-buffer API is needed for this selected boundary, and no such factory is introduced.

Keep Uri/Binary enum names and numeric identities unchanged. Their existence and function static return-type metadata do not establish a public construction route. Some Uri consumer branches call StringValue while its getter requires String kind; atomic range handling also differs for Binary. These static findings require coordinated review before any activation, not a reflected negative launch or a claim of a new public-path defect. Existing production behavior remains unchanged.

Future activation needs an explicit owner use case and exact immutable specification/adoption record, representation/lifetime/budget policy, complete getter/cast/equality/hash/map-key/EBV/serialization/static-metadata/all-host review, positive and caught-negative tests, full gates/API/binary evidence and actual owner/native acceptance. This prerequisite does not silently waive any existing request. Existing binary comparison/canonicalization/native semantics remain part of the broader acceptance work.

PV-T06 is complete only as a Core disposition with scope. No API freeze, PV-01/R3 closure, native budget or publication acceptance follows. Next PV-L01 handles private legacy evidence. [XDM 3.1 immutable basis](https://www.w3.org/TR/2017/REC-xpath-datamodel-31-20170321/) and the [F&O 3.1 constructor/casting review reference](https://www.w3.org/TR/2017/REC-xpath-functions-31-20170321/) are recorded separately in ADOPTION.json; the latter is not a reconstructed historical adoption receipt.
