## Adapter and controls

[tools/Probe.cs.txt](tools/Probe.cs.txt) implements the deliberately small adapter:

- Handles wrap original AssessedSchemaType and AssessedElementDeclaration objects; a reference-based issuance table checks membership. Independent identical schema compilation has an equal digest but a distinct authority.
- Native read-only AssessedElement state supplies ISchemaNodeFacts and immutable scalar ISchemaTypedValue cells. Cells contain the actual decimal plus separate current type/original assessment evidence. A copied cell container is refused before enumeration.
- Each direct node wrapper exposes its original facts and receives Core-side prototype attachment only when its typed value is read. The prototype stores the complete evidence object, not just an origin label.
- Copy uses native AssessedDocument.Copy: original state and origin remain, snapshot identity changes. Independent assessment under the same compiled schema retains component handles but receives a distinct origin.
- Only identity comparison is implemented as an authority operation. Resolution, derivation, affiliation and closure explicitly return Unsupported. The trial does not implement a bound ISchemaAssessor/ISchemaAssessmentAdvisor; issuance is enforced by the local producer/consumer composition, not claimed as an implemented public binding protocol.

## Important cast observation

| Actual API/VM expression path | Plain numeric result | Holder evidence |
| --- | --- | --- |
| Identity, let, array, map, function | 10 | Preserved |
| data on original/copied direct decimal node | 10 | Preserved |
| xs:decimal on already decimal input | 10 | Preserved |
| xs:integer on decimal input | 10 | Dropped |
| Arithmetic / two-value addition | 11 / 15 | Dropped |

The earlier synthetic probe cast an integer to decimal and observed dropped evidence. The same-type decimal path instead returns the existing evidence-bearing value. This is observed engine behavior, **not** adoption of a complete constructor/provenance rule. Before production integration, decide whether a no-op constructor preserves existing original evidence or constructs fresh target evidence, distinguish that from granting new assessment authority, and qualify every affected fast path. Do not claim that all casts drop provenance.

## Limits and next step

Wrappers are bound directly as variables. Their delegated axes, parent and children return the existing inner provider nodes; they do not wrap a whole tree or propagate V5 facts through arbitrary navigation. Whole-document traversal, XQuery copies, XSLT copies, native QName/list/union construction, actual host-context capture, worker/persistent lifetime and concurrent invalidation remain unqualified. Legacy schema annotations are still needed for the VM's typed-node routing. The descriptor/read helper in the V5 proposal remains unimplemented production shape.

No new allocation/timing, retained-memory, ABI, full conformance or final performance result is claimed. The holder's previously known allocation/equality limitations remain. Production source stays Core 1.34.2/c88eea43; this step adds no engine semantic change and runs no new full-product gates. C45, stable manifest, consumer qualification, budgets and four-owner API freeze remain pending.

Next: disposition the same-type constructor provenance rule against immutable specification sections, then extend the isolated adapter to a whole navigable snapshot and verify original facts/carrier behavior on actual navigation. Only after that evidence should the selected production carrier and runtime integration be implemented and all product gates rerun.
