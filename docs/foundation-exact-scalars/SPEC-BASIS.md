# Exact comparison, key and bounded-string adoption basis

4 November 2026, before source edits; base 89cefa47 / 1.48.0. Adopt immutable XPath REC-xpath-31-20170321 sections 3.7.1/3.7.2 for singleton primitive numeric value/general comparisons and the existing arithmetic grammar basis. Adopt Functions and Operators REC-xpath-functions-31-20170321 sections defining op:same-key and fn:string (exact dated W3C source inspected before implementation). Preserve prior XSD decimal/integer and IEEE exact-value adoption. No Boolean comparisons/logical operators, sequences, floating-point query arithmetic or general serializers are adopted.

Scope: keep existing bosak-exact-arithmetic-v1 queries and ordinary string/Boolean selection. Add separately identified bosak-exact-scalars-v2 for one numeric comparison per expression level (eq/ne/lt/le/gt/ge and singleton =/!=/</<=/>/>=) and top-level fn:string/string around the finite numeric grammar. Numeric comparison operands must be Integer/Decimal; Boolean results cannot feed numeric arithmetic/comparisons. Chained comparisons refuse compilation. No function aliases except unprefixed string and correctly bound fn:string, no arbitrary function nesting or typed/schema inputs. Existing input/intermediate quotas and raw operation lifetime/cancellation checks remain.

Comparison must not allocate powers or padded strings from a huge scale difference. Compare signs and decimal orders first; exact coefficient digit count uses integer/UInt128 estimates and bounded threshold correction. Equal decimal order implies any necessary alignment is bounded by admitted coefficient width. Numeric equality and order preserve exact mathematical values without CLR narrowing.

Replace numeric map-key canonical strings with normalized coefficient/scale plus NaN/infinity sentinels. Finite IEEE values convert to their exact bounded decimal pair, preserving the existing op:same-key policy including NaN and signed zero. Numeric hash values may change; hashes are process-local, not persistent storage identities. Existing nonnumeric key rules and XdmValue CLR representation equality remain. Global XdmMap has no query limits; its work is bounded by already-owned coefficient width and the intrinsic IEEE exponent range, never by exponentiating a supplied decimal scale. Full map construction/query syntax remains outside the numeric session profile.

Top-level string conversion is bounded by min(int.MaxValue,max(MaxNumericDigits+2,MaxDecimalScale+3,5)): numeric sign/point/padding bounds and intrinsic Boolean text length, not workload defaults. Format only after numeric admission and output-size checks, with raw availability checks before/after. This is one copied scalar string, not XML/JSON/XSLT serialization or a hard aggregate-memory/time guarantee. Keep legacy XdmValue.ToString checked; explicit fn:string does not enable implicit formatting elsewhere.

Source feature version 1.49.0; public signatures/fields/friend grants remain unchanged. Optimize normalization's failed divisibility checks so cached normalized map keys need no quotient allocation. Update earlier negative tests only where this new scope now provides positive coverage; preserve all historical dossiers. Qualify integer/decimal/IEEE key/hash equivalence, extreme scales, migration of prior wide-map refusals, scalar syntax/types/lifetimes, refusal/allocation costs, full tests and exact frozen gates. No native owner acceptance, full numeric/schema/all-host support, C45/freeze, tag/package/publication or final release SemVer selection. Earlier typed-default source migration remains applicable.

Reference clarification (after qualification; adopted scope unchanged): [XPath 3.1 dated Recommendation](https://www.w3.org/TR/2017/REC-xpath-31-20170321/), sections 3.7.1/3.7.2; [F&O 3.1 dated Recommendation](https://www.w3.org/TR/2017/REC-xpath-functions-31-20170321/), sections **17.1.1 op:same-key** and **2.3 fn:string**.
