# F140-01 — Observed contracts and proposed compatibility requirements

30 October 2026. Source basis and exact metadata are pinned in [the baseline](README.md). Observations describe existing code; proposed preservation requirements are not new semantic acceptance.

| Boundary | Observed source contract | Proposed freeze requirement / qualification |
|---|---|---|
| Node implementers | `IXdmNode` requires kind/name/value, parent/document, axes, identity/order, URI and serialization members. Other metadata has default implementations. | Enumerate required versus default members separately. Preserve existing implementers and defaults; qualify real XmlDb unchanged binaries, not just a synthetic node. |
| XML kind values | `XdmNodeKind : byte` is flags: None=0, Document=1, Element=2, Attribute=4, Text=8, Comment=16, ProcessingInstruction=32, Namespace=64, All=127. | Retain values and XML meaning. Do not add JSON kinds as storage flags or infer a persistence migration. Other enums/defaults are fully captured for review. |
| Identity and order | `IXdmNode.IsSameNode` and `DocumentOrder` are provider contracts; the latter documents 0 for unknown. | Agree same-node symmetry, hashing and mixed-tree/provider ordering. XmlDb owns its snapshot-relative identity and lease rules; schema wrappers must retain source identity without treating component identity as node identity. |
| Typed values/errors | Nodes expose `XdmValue TypedValue`; `HasNoTypedValue` defaults false. Its documentation identifies FOTY0012 for nodes without typed value. Schema annotations/declarations are nullable expanded-name tuples, with flags defaulting false. | Preserve ordinary untyped behavior. Full XSD 1.1 needs original component/universe provenance and list/union transport beyond name/flag projection. No same-QName authority inference. Qualify invalid, unsupported and error paths separately. |
| Atomic/container layout | `XdmValue` is a readonly struct with kind/integer/double/reference/schema-name fields; value factories include node, sequence, map, array, function and external values. `XdmSequence` contains an interface reference; its enumerator is a mutable struct. | Keep source and compiled layout compatibility under review. Field-shape capture is not measured ABI proof. Values and nested containers may retain provider objects; copying a struct does not copy a snapshot or extend its validity. |
| Lazy sequence ownership | `IXdmSequence` offers `TryGetLength` and `GetEnumerator`; `IXdmSequenceEnumerator` offers `Current` and `MoveNext`. Neither declares disposal or cancellation. `XdmSequence.Enumerator` starts underlying enumeration on first movement. | Specify early termination, abandoned/deferred results and lease release using actual provider ownership. Do not add required disposal members or promise automatic cleanup without an accepted compatible design. |
| Single-pass producers | `ISinglePassSequence` documents at most one enumeration; producers guarantee duplicate-free document order so engine normalization can be skipped. | Preserve marker meaning; consumer qualification must include repeat-enumeration refusal, early exit and ordering. It is not a general thread-safety or resource-disposal guarantee. |
| Compile/evaluate environment | `CompileOptions` has init-only options including compatibility/profile, namespaces, typing and a `XmlSchemaSet` reference. `EvaluationContext` exposes mutable loaders, constructors, schema resolver/set and schema-aware flag. | Define which inputs are captured at compile time versus evaluation time and cache identity. An init-only reference does not make the referenced schema set immutable. Existing setters do not certify safe mutation/reentry across executions. |
| Existing native bridge | `XdmElementAssessment` carries Owner/State objects and bounded anonymous-element-only/decimal facts on in-memory XML. Existing annotation helpers also expose `IXmlSchemaInfo`/`XmlSchemaSet`. | Preserve this accepted bounded behavior and copy/strip boundaries. Do not reinterpret object retention as a general public session, complete component model or independent compatible-universe proof. C45 remains pending. |
| Resources, cancellation and concurrency | Runtime exposes controlled-resource contracts and legacy hooks. Node/sequence interfaces provide no universal evaluation cancellation token or ownership protocol. | Retain host authority and explicit provider/session ownership. Qualify cancellation, resolver faults, disposal and independent evaluations on actual consumers. No general concurrent-disposal promise is inferred. |
| Layer direction | Core is the common XDM dependency. Concrete provider, Schema validator and XmlDb storage implementations have their own ownership. | Core production assemblies must not reference the concrete Schema/XmlDb/licensing implementations. Test integration may exercise them. XmlDb Core/Storage stay independent of Bosak XDM; its adapter bridges them. |

Source review entry points: `src/Bosak.XPath.Core/Xdm/{IXdmNode,IXdmSequence,ISinglePassSequence,XdmValue,XdmSequence,XdmNodeKind}.cs`, `src/Bosak.XPath.Api/CompileOptions.cs`, `src/Bosak.XPath.Runtime/Vm/EvaluationContext.cs`, and `src/Bosak.XPath.Providers/XDocument/XdmElementAssessment.cs`.
