# Switch fallback ordering — 20 October 2026

Source patch **1.22.1** rejects an `xsl:when` or `xsl:otherwise` after the first `xsl:fallback` inside `xsl:switch`, with `XTSE0010`. Valid trailing fallbacks remain accepted and ignored. This fixes native `switch-901` without changing its expected error or stylesheet.

The normative basis is the pinned qtspecs revision `72f222929768b411d8e88d96a1a8740483290078`: `specifications/xslt-40/src/element-catalog.xml` declares the switch content sequence `when+`, `otherwise?`, `fallback*`. The prose in `xslt.xml`, section `xsl-switch`, explains that fallback children are ignored by a 4.0 processor; that does not authorize branches after the fallback tail. The original baseline manifest and hashes are included in the separate harness PR; the exact pinned source files above are the normative basis for this engine patch.

Twenty local regression cases cover both processor profiles and stylesheet versions 3.0/4.0: twelve invalid layouts (fallback before the first when, between whens, or before otherwise), and eight valid multiple-trailing-fallback layouts with/without otherwise. The tests first reproduced **12 failures / 8 passes** before the correction. Validation is static, including named templates before invocation; a trailing fallback containing `error()` is not executed.
