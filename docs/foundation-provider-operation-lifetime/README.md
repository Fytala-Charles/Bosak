# TA-19 provider-operation lifetime prerequisite

5 November 2026. Development source **1.65.0**, uncommitted on ec6daa0e538fe3c4e2ebc54177a1daeda5834b38. This internal prerequisite implements TA-18's raw-owned provider-call scope; public construction stays Unsupported.

`QuerySourceSession.Operation.CallProvider` requires a real optional `IQueryOperationLifetime` from the exact provider selected by its future caller. It admits at most one provider identity per raw operation, acquires once lazily, and serializes provider-touching calls by refusing overlap/reentrancy. The guarded callback receives availability checkpoints and result delivery is checked again after it returns. Provider callbacks never run under state locks.

Raw callback/task completion closes the call scope immediately and waits for actual Enter/work tails, then provider admission cleanup, then the existing fixed raw leases. Run blocks through this completion; RunAsync awaits it. Session drain remains pending because the original session admission remains held. Canceling a drain wait does not cancel work. Raw cancellation/session close denies resumed delivery. A retained operation reference cannot retain an active admission after raw completion. Cleanup attempts every fixed lease and preserves primary, provider-cleanup and original reverse-order fixed-cleanup failures, including supplied aggregate exception objects.

## Qualification boundary

18 new internal tests exercise actual Run/RunAsync/Operation/DrainAsync, blocked Enter and provider callbacks, cooperative cancellation and close, wait cancellation, overlap and reentrancy, failed retention, independent raw operations, repeated completion, cleanup-only/combined failures and blocked cleanup. A temporary exclusive file stream remains writable while the provider is on stack and closes through the admission's original release callback. These are deterministic barriers with bounded watchdog waits, not intentional unhandled diagnostics.
