* feat(XSLT): REQ-118 4.0-S8 xsl:array/xsl:array-member and xsl:switch

XSLT 4.0 draft §21.1.2: xsl:array builds an XdmArray — @select contributes
one singleton member per item; @for-each contributes one member per focus
item whose value is the whole per-item sequence; sequence-constructor
content treats each ordinary item as a singleton member while a nested
xsl:array-member contributes exactly one sequence-valued member (the spec's
JNode wrapper is unnecessary because XdmArray members hold sequences
natively). XTTE4060 is unreachable without a JNode model.

XSLT 4.0 draft §8.3: xsl:switch coerces its @select to a single atomic item
(XPTY0004 otherwise) and matches xsl:when branches by coercing each @test
to atomic items and comparing with the selector under general-comparison
(=) semantics, NaN never equal, using the default collation in scope for
the instruction. xsl:when/xsl:otherwise under xsl:switch gain an optional
@select (mutually exclusive with content, XTSE3185); under xsl:choose the
attribute stays inert so choose behavior is bit-identical to 3.0.

Both instructions are known at every effective version (added to
KnownXsltElementNames) so version="4.0" stylesheets in forwards-compatible
mode still execute them (§3.8.2/§3.8.3 make the surfaces version-independent;
the supported-version ceiling deliberately stays 3.0 per the frozen W3C
forwards-* catalog tests).

Static checks in ValidateInstructionTree: xsl:array/xsl:array-member
@select+content XTSE3185 (xsl:fallback exempt); xsl:switch requires @select
and (xsl:when+, xsl:otherwise?, xsl:fallback*) shape XTSE0010; when/
otherwise @select+content XTSE3185 only under xsl:switch.

StreamabilityAnalyzer mirrors the xsl:map cases for xsl:array (@for-each and
@select surfaces), xsl:array-member and xsl:switch.
