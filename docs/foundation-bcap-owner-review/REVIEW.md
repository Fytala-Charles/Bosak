## Concrete boundaries that must not be overstated

- MaxMessages bounds the **message count**, not an individual message's bytes. Output serialization limits do not bound tree construction, compiler memory/time, a single XPath evaluation, native allocation or reserved worker stacks. Long-expression cancellation can still need the owner's process deadline/termination control. Decide now whether the product needs another Core limit before API freeze.
- The reused XsltCapturedOutput API is detached managed data, but this packet does not certify deep immutability: its Bytes getter returns the backing array through IReadOnlyList<byte>, and OutputProperties exposes a mutable properties object. Review the consumer's snapshot/copy policy or required internal hardening. Receipt snapshots and original exception graphs have different mutability/privacy properties; do not conflate them.
- The private owning prototype has a bounded explicit argument path and internal capture/input limits. It does not implement the public invocation object or every future constructor/profile. Declared RawResult refusal and public limit plumbing must be implemented/tested in R3 before claiming a shipping contract.
- Core original-error collection is opt-in/lazy for the private capture path. It preserves observed serializer objects alongside existing classifications. It does not make arbitrary provider exceptions thread-safe, immutable, safe to serialize or proof that a native release succeeded.
- Synthetic snapshot release tests exercise actual Core lease paths. They do not repair XmlDb OpenPinnedSnapshot fault latching/cleanup masking or qualify actual reader/generation/admission release. Current Core signatures must represent known needs, but native implementation evidence stays with the owner.

No mandatory new signature is invented by this packet. Source-identified limits and any owner's precise unmet requirement must be resolved explicitly rather than hidden behind a blanket acceptance or deferred until after freeze.
