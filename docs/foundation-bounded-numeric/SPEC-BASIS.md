# Bounded exact arithmetic profile adoption basis

4 November 2026, before source edits; base 6d5a46ae / 1.47.0. Adopt the immutable [XPath REC-xpath-31-20170321](https://www.w3.org/TR/2017/REC-xpath-31-20170321/) sections 3.1.1 (numeric literals), 3.1.2 (variable references), 3.5 (arithmetic), A.1 (grammar/precedence) and B.2 (operator mapping), alongside the dated XSD Datatypes REC-xmlschema11-2-20120405 decimal/integer basis retained in the previous exact numeric dossiers. No later editor revision, floating-point or division semantics are adopted. Normative decimal/integer addition, subtraction and multiplication preserve exact values; capacity refusals are host policy, not Invalid assessment outcomes.

Implement a separately identified public opt-in bosak-exact-arithmetic-v1 profile using the existing reviewed session and numeric limit signatures. The prior ordinary string/boolean profile and all legacy XPath/XQuery/XSLT execution remain selected as before. Numeric selection requires numeric literal/operator syntax; a bare variable keeps its previous ordinary profile. Scope: source-free integer/decimal literals, unprefixed numeric variables, parentheses, unary signs, +, -, *. No functions, node atomization, division, exponents, comparisons, maps/arrays, prefixed/EQName variables, strict typing or JIT in this profile. Unsupported syntax/options and compile-time capacity return Unsupported; dynamic capacity throws NotSupportedException. Missing variables use XPST0008 at dispatch. No implicit legacy parser/VM fallback or decimal rounding.

Lexical digit/scale quotas precede coefficient construction; count all supplied literal digits and fractional places before normalization. Validate every supplied binding, including unused values, using its current representation: raw CLR decimal coefficient/scale before normalization, exact-holder coefficient/scale as already normalized by its owner. Original creation work/lexical scale of an already-owned normalized holder is not recoverable and is not claimed bounded. Refuse private markers and non-integer/decimal inputs; borrowed focus/membership still obey existing admission rules. Every intermediate coefficient, aligned operand and result must fit MaxNumericDigits; supplied result scale is checked before normalization. Preflight alignment via remaining digit capacity before Pow/multiply; same-sign sums and products use bounded threshold subtraction/division before allocating results. Intermediate refusal is possible even when later cancellation could yield a small final result. No implicit workload defaults or hard total-memory/CPU/expression-length guarantee.

Compile the finite arithmetic grammar iteratively without invoking the legacy numeric AST parser. Capture the actual compiler's immutable static options/namespaces/profile/limits. Evaluate an immutable postfix plan using pooled stack storage cleared on return. Check raw operation availability/cancellation between instructions and around arithmetic, retaining leases through actual work. A BigInteger library call is not forcibly preemptible. Public signatures, XdmValue instance layout and friends remain unchanged; source feature version 1.48.0. No schema operations, full numeric profile, all-host/native acceptance, C45/freeze, tag/package/publication or final SemVer selection. Prior typed-default source migration remains applicable.
Only base integer/decimal carriers without derived or user-defined schema annotations are admitted in this first arithmetic profile. Descriptive names cannot establish schema arithmetic semantics; derived/provenanced operations remain a later profile.

Capacity thresholds are bounded metadata derived from the selected digit limit and can contain one extra threshold digit. The quota applies to admitted/evaluated coefficients, not a strict byte count for all temporary metadata.
