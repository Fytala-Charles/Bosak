<p>Test definitions only — 17 October 2026</p>

All tests below are **planned**, with no engine implementation or pass claim. Follow the [proposed contract](REQ-131-TEXT-INSERTION-CONTRACT.md). Use independent expected output/golden bytes, not expectations generated by the production escaping/layout code. Start fixtures from the published 1.17.0 baseline and preserve any initial failing results separately.

| ID | Fixture or action | Required evidence |
|---|---|---|
| T01 | Append `Label: ` to an eligible explicit-close result parent | One new xsl:text; exact ordinary output text and source golden; original snapshot unchanged. |
| T02 | Empty string | Explicit paired instruction, empty TextValue, zero-length payload range, null PayloadNode; visible new instruction identity and one history step. |
| T03 | Spaces, TAB, LF, CR, CRLF alone and in combinations | No trimming; exact result code points; TAB/CR/LF numeric source references; no physical newline convention introduced by the payload. |
| T04 | `&<>`, quotes, `]]>`, `&amp;` and `</xsl:text><evil/>` | Literal output, deterministic XML escaping, no injected element/DTD/attribute and exact payload source extent. |
| T05 | `{customer}`, doubled braces, `$missing`, `{1 div 0}` and `{doc('https://invalid.example/')}` | Literal characters under absent/no/yes inherited expand-text; explicit local no override; no parse/evaluation/resource call. Unsupported override contexts refuse. |
| T06 | Non-BMP, combining forms, payload U+FEFF and multilingual text | Exact unnormalized logical string, scalar boundaries, encoded-byte and UTF-16-column evidence. |
| T07 | UTF-8 BOM/no-BOM, UTF-16 LE/BE BOM with matching declarations | Envelope/URI/declaration retained, exact edits/replay, untouched bytes and correct decoded payload. Invalid encodings/declarations retain refusal. |
| T08 | NUL, illegal controls and isolated high/low surrogates | InvalidPayload with no candidate or encoding replacement; null constructor input throws; empty remains supported. |
| T09 | Existing/default-only/aliased/rebound/colliding XSLT prefixes | Correct expanded instruction name; deterministic local declaration only when needed; old namespace and payload bytes unchanged. |
| T10 | Compact, indented, comments/PIs, nested child markup and uniform LF/CRLF/CR | Exact PreserveSource and Readable goldens; two-space compact fallback; direct gaps only; no payload indentation. |
| T11 | Mixed newlines/indentation, mixed parent text, direct CDATA, effective preserve and ancestor preserve/default reset | Existing scope refusals or UnsupportedFormatting as specified; no silent fallback, no candidate or mutation. |
| T12 | Append text twice; text then value-of; value-of then text | Fresh snapshot-owned targets each time; stable explicit edit evidence and ordering; generated literal xsl:text does not block the next supported operation. |
| T13 | Existing literal xsl:text containing significant whitespace; unsupported expanding/DOE forms | Protected existing instruction bytes and all old descriptors preserved; only proven literal forms newly covered; unsupported forms refuse rather than broaden blindly. |
| T14 | Duplicate-looking siblings and represented old whitespace | Total injective old-node map including ancestors; explicit new instruction/payload IDs; empty payload has no fake descriptor; ambiguous evidence refuses. |
| T15 | Apply SourceEdits independently to original source; mutate exports/collections | Exact candidate replay, unchanged-span byte comparison, defensive copies and read-only collections. Payload logical length is not mistaken for source range length. |
| T16 | At/over original limit; escaped amplification; UTF-16 physical size; formatting overhead/shrinkage | Exact inclusive byte limit, checked counts before allocation, SizeLimit without candidate, no value-of budget regression. |
| T17 | Pre-cancel and deterministic cancellation during counting/traversal and before final return | Cancelled, unchanged input, no partial candidate or leaked state; include uncancelled controls without timing-sensitive assertions. |
| T18 | Foreign snapshot/target, same IDs/bytes from another inspection, concurrent independent proposals | Reference ownership enforced; immutable original reuse is valid; consumer revision staleness is checked at Apply, with isolated concurrent outcomes. |
| T19 | Unsupported module/static/profile/component inputs; hostile-looking literal payload | Denied resolver/file/network/extension calls; no new external/static authority; complete original/candidate validation. |
| T20 | PreserveSource versus Readable with identical text payload | Independent ExactBytes text/XML outputs where deterministic; significant literal whitespace retained, ordinary serialization escaping and adjacent/empty result-text behavior accounted for. |
| T21 | Prior public value-of/readable insertion suites and captured 3.0/4.0 profiles | All prior successes retain bytes/default behavior; mixed-operation literal-text coverage explicitly tested; no unrelated refusal/gate changes. |
| T22 | Fresh package-only API consumption and assembly/cache/output provenance | Exact reviewed head then exact merge; no project references/friend assembly spoofing; public capability and new types usable; all engine tests and frozen gates pass. |
| T23 | Braid capability/input/review/selection and explicit Apply | Literal input is not labeled XPath; exact candidate and complete changed spans frozen; source/policy/cancellation changes invalidate review; new instruction selection works even with empty text. |
| T24 | Braid undo/redo, validation, preview, new-file export and independent reopen | One history entry, exact restoration under new revisions, old authority stays stale; new golden output, file/hash/source/engine evidence; original file untouched. |
| T25 | Independent native consumer review | Record observed encoding variants and literal whitespace presentation, Apply/selection, history and run/export workflow; do not infer unobserved DPI/accessibility/trust or manual hash audit results. |

Each payload group needs both a happy-path control and a refusal/edge assertion where applicable. Native review follows the engine delivery and Braid integration; earlier REQ-129 acceptance cannot be reused as evidence for a new command.

Implementation completion requires actual receipts for applicable engine/package groups. Consumer acceptance remains independent and must record its own delivered profile and remaining observations. Review this matrix before implementing the proposed API.
