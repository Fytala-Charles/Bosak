# Strict native assessment request prototype — TA-48

The isolated adapter now accepts public **strict assessment requests over provider-owned captured documents** and returns native Valid, Invalid or Unsupported results. Only complete Valid publishes a validated root. The final Release build has zero warnings/errors and **59 controls pass**: 34 carried container/node controls plus 25 strict-request controls. Counts overlap earlier packets and are not a complete native suite.

[Strict assessment](prototype/NativeStrictAssessment.cs) captures the episode constants, checks mode/handles/limits/input ownership, borrows a request lease and delegates to the unchanged bounded native assessor. The provider checks the request snapshot and cancellation before publication. Only successful native documents are projected into a new owned output snapshot. Exceptions revoke any unpublished output and release the request admission; caller XML and assessor resources are not disposed.

Successful output preserves the request's original source identity but receives a **fresh current snapshot and original assessment**. Normalized native XML is never mislabeled as the unchanged request snapshot. Its element facts retain actual native declarations/types and exact decimals. A public `data($node)` consumer test admits the output and reads its typed decimal value. The root retains no typed value, as qualified by the carried node controls.

Invalid and native Unsupported results expose no validated root. They may retain original attempt evidence whose completeness is false; no success is inferred from diagnostic absence or truncation. Native diagnostic codes/messages are preserved, with no fabricated source location. Finite defaults are eight diagnostics and 4,096 aggregate **code plus message characters**; positive caller limits only tighten them. Entries that do not fit are omitted and truncation is flagged independently of assessment status.

[Request tests](prototype/NativeAssessmentTests.cs) cover success/source/snapshot/engine evaluation, invalid and unsupported results, count/character truncation, invalid limits, unsupported lax/type requests, owned/foreign declarations, foreign advisor inputs, poisoned unknown-input getters, cancellation, episode bounds, request mutation/revocation, caller isolation, output survival after request disposal and independent repeat assessments. The original request admission is released after every completed native attempt and remains caller/provider-owned.

**Scope limits:** capture and output handoff helpers remain internal to this test-only provider. `AssessmentResult.Output` supplies the exact owned input for the consumer test; generic public consumer handoff and host composition are not claimed solved. Arbitrary `ISchemaAssessmentInput` implementations are Unsupported before getters, even when they claim equivalent bindings. Preassessed transport inputs remain distinct from request captures. Lax/type, compatibility, construction, persistent storage, concurrent mutation/use and broader XSD semantics remain unsupported or separate work.
