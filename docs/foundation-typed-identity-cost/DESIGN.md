# Allocation attribution and change boundary

TA-05 created a normal EvaluationContext for every identity call. Its mutable function dictionary caused XPath31Expression.Evaluate to copy the standard function template during FunctionLibrary.Populate. The existing CreateIsolated factory tags the new context with the immutable shared-table mechanism already qualified in the function-table sharing slice. Population still runs, stamps the compiled compatibility and installs the appropriate standard template; no special function-name bypass is introduced.

The production change selects that existing factory on the typed identity route. It does not modify public context construction, the compiler, function population, profile selection, descriptor generation, resource policy, snapshot membership or scalar validation. Mutable variables, namespaces, document state and VM execution remain per-call. There is no context pooling or raw-operation/context retention by resident evidence. A direct guard probe mutates one call's variable state and verifies a subsequent call receives a different context without that state.

Two controlled attribution cases execute the same compiled source with fresh mutable and isolated contexts, preserving both variable identity output and an actual standard function result. Each mode warms 100 times and measures 1,000 calls. The current owner-bound compiled identity test is unchanged from TA-05 and repeats the same held-operation workload, including current endpoint/input/type checks, closed resources and pre/post marker/representation validation. Its 19,256-byte reduction matches the registry-copy difference in both independent comparisons. Payload getters remain unexecuted on warm reuse.

The new tests record an actual default typed-profile fingerprint before and after the optimization. The comparison verifier requires exact equality. All public API source remains byte-identical to TA-05; only the runtime factory selection, its source history row, the patch version and the new cost tests change. Existing internal constructor overloads remain intact. General capture/evaluation still refuses on this capability; public assessor/ReadTypedValue guards are not lifted.

The immutable input dossier retains the prior qualified source/binaries and 23,360-byte result. Diagnostic attribution rebuilds use unchanged 1.57.0 implementation source but embed the new commit in assembly informational versions. Their actual eleven binaries and loaded baseline hashes are retained separately, rather than claiming those images match the earlier qualification. Final qualification uses one complete 1.57.1 cohort with loaded hashes, full tests and exact frozen skip maps.

Remaining 4,104-byte call allocation includes fresh context creation, VM dispatch, closed policy and operational guards. This slice establishes the local saving and preserves isolation; it does not qualify total retained bytes, elapsed time, native callback cost or PF-01–09 owner budgets. Those representative workloads remain release gates.
