# Exact quotient and remainder adoption — 4 November 2026

Recorded before implementation, base e8dc3154 / source 1.49.0. Adopt [XPath 3.1 dated Recommendation](https://www.w3.org/TR/2017/REC-xpath-31-20170321/) section 3.5 and [F&O 3.1 dated Recommendation](https://www.w3.org/TR/2017/REC-xpath-functions-31-20170321/) sections 4.2, 4.2.5 and 4.2.6 for primitive integer/decimal idiv and mod. Integer quotient truncates toward zero; remainder has the dividend sign and integer kind only when both inputs are integers. Zero divisors raise DivideByZeroException carrying FOAR0001; this host exception mapping is scoped and is not full standardized error-graph integration.

New bosak-exact-quotient-v3 / bosak-exact-quotient-static-v3 applies only when idiv/mod is present. Earlier v1/v2 grammar and descriptor identities remain. Operators share multiplication precedence and associate left. Comparison/string composition uses existing scalar dispatch. No public metadata change; source feature 1.50.0.

All supplied coefficients/scales and necessary aligned coefficients must fit captured limits before power/alignment allocations. Magnitude comparison short-circuits quotient zero/remainder dividend, including extreme scale gaps. Equal magnitudes short-circuit unit quotient/zero remainder. Other operands use bounded common-scale BigInteger division/remainder; conservative refusal is permitted even if the eventual result could fit. There is no rounding, implicit CLR narrowing, floating query arithmetic or decimal div adoption. Availability callbacks bracket arithmetic; no hard time/aggregate-memory guarantee. Preserve exact map-key semantics, schema/native/owner/freeze/publication boundaries and historical receipts. Qualify signs/types/precedence, wide coefficients, extreme scales, quotas/errors/lifetimes and full frozen gates before completion.
