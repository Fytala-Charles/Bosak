## Consumer scope decisions

The proposed first profile is sufficient for the requested bounded delivery:

| Decision | Consumer disposition |
|---|---|
| One coordinated feature | Accept Rename and Delete together in one implementation PR, preserving existing Create; one subsequent Braid integration PR |
| Targets | Accept imported/engine-created paired/self-closing ordinary no-namespace elements beneath a template through a literal-result-only ancestor chain |
| Attributes/context | Accept the declared constant-result-attribute profile and whole-module restricted coverage; computed AVTs, targets beneath control instructions, preserve-space and other excluded contexts remain unsupported |
| Populated Delete | Required and included: remove the entire selected element plus owned attributes, instructions, text, comments/PIs and descendants; no unwrap or child retention |
| Boundary merge | Accept at most one direct-parent merge of immediate whitespace-only text siblings; other unproved/non-whitespace merges explicitly refuse |
| Version/host | Accept declared effective 3.0/4.0 in the existing Legacy authoring host; no selectable Draft-host support is inferred |
| Existing Create compatibility | Preserve its existing eligibility/formatting. Advertise the complete lifecycle only within the intersection of operation profiles |

These limits are consistent with the request's supported-profile/refusal boundary; they do not replace populated deletion with empty-only deletion. Braid must disclose unsupported targets and the destructive whole-subtree intent rather than advertise unrestricted element editing.

## API and evidence assessment

Separate additive capabilities, operation-specific opaque targets/results and internal evidence construction meet LE01. Equal-byte foreign snapshots and numeric IDs do not grant authority. The Changed/NoChange/Failure distinction is appropriate; equal-name Rename still requires valid original authority and coverage, and produces no candidate or Apply permission.

Rename's one/two exact name-token edits and explicit same-original coordinate convention meet the paired/self-closing source-preservation requirement. Candidate offsets include checked prior deltas; complete replay must equal candidate bytes. All attributes, descendants and namespace declarations remain unchanged outside the allowed tokens. Delete's one full-element removal, zero-length candidate anchor and actual direct-parent selection match the requested history/navigation contract.

Disjoint exhaustive original/candidate node partitions and per-owner attribute accounting cover the larger subtree proof that existing instruction deletion cannot supply automatically. The limited merge policy requires actual inspected candidate identity/value and unchanged source fragments; it avoids inventing descriptors or concatenating normalized logical strings as proof. Namespace declarations remain accounted for wherever inspection represents them.

Independent physical source, name, descriptor/depth, edit and copied-evidence budgets are concrete and suitable for the consumer boundary. The 16 MiB evidence budget is a ceiling with explicit refusal, not a guarantee that every source below 8 MiB can produce reviewable evidence. Braid's smaller projection/review limits remain independently enforceable. Cheap preflight bounds, iterative depth checks before recursive work, immutable copied evidence and cancellation immediately before success/NoChange remain mandatory implementation obligations.

The LE01-LE18 ownership mapping correctly separates engine source/identity/coverage proof from Braid current-session/license/atomic Apply/history authority and later worker/export/reopen/native acceptance. Existing creation/attribute/text/expression contracts must retain their accepted behavior.

## Items to verify at implementation review

These are declared design obligations, not findings that the proposed scope omits:

1. Publish and enforce the exact instruction/attribute/expression allow-list and whole-module denial rules before any resource-capable compilation; prove no ambient acquisition with instrumented callbacks.
2. Exercise populated nested deletion, all removed attributes/descriptors, parent/sibling survival, namespace resets/rebinding and both supported/refused boundary merges across supported encodings.
3. Prove strict replay/range translation for both paired-name edits, complete survivor correspondence, evidence-size/depth preflight, immutable export copies, concurrency and cancellation, including NoChange after eligibility checks.
4. Deliver both operations in the same implementation PR, with public XML documentation and full required engine/regression gates. Later verify public package provenance and the complete Braid lifecycle, including source changes that leave sample output unchanged.
