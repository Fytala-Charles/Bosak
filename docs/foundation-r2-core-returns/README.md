## Concrete implementation boundary now recorded

W1 needs a **neutral source-admission path separate from optional schema evidence composition**. The current private SchemaEvidenceKernel requires an issuer and assessment; it must not be reused for ordinary XmlDb by inventing an assessment token. The public review draft already permits absent assessor/origin. An implementation can reuse operation lease machinery while keeping ordinary input availability/identity separate from authenticated schema facts. No new public acquisition manager or concrete backend dependency is selected.

For O2, the intentionally small public static-context mirror is explicitly subject to Schema's concrete advisor needs. Core's internal effective-context capture and a fingerprint do not prove every required observable context field is present in the public contract. An owner-demonstrated missing field is a real R2 signature decision, not a performance optimization to defer past freeze.

For O4, source inspection of the pinned XmlDb cleanup paths is not fault-injection evidence. Core's synthetic acquisition/rollback qualification cannot certify actual native failure recovery. The owner must fix or explicitly disposition required failure and concurrency scope before actual consumer acceptance.

R2 remains **InReview** with two scoped Core returns recorded and five external role returns pending. R3 remains gated by the corresponding accepted contract scope and provider facts under C139-01/C139-02. Planning, fixture inventory and package preparation can proceed; these returns do not authorize a blanket public implementation or release.
