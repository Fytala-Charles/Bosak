# Native provider public consumer handoff — TA-49

A **separate consumer assembly** now assesses a document, obtains the exact provider-owned snapshot admission and evaluates public `data($node)` without internal casts, friend access or reflection. All **ten consumer controls pass**; both consumer/provider and workload Release builds have zero warnings/errors. Production Core and native Schema sources remain unchanged at the qualified 1.81.0 cohort.

[The experimental provider facade](provider/NativeProviderSession.cs) owns its bound engine session. Each successful result owns its output input and exposes `OpenSnapshot`, which admits that exact input/origin/lifetime into its original session. It cannot adopt an arbitrary annotated root or foreign source. The facade is an isolated provider assembly, not a new Core API or a production Schema export.

[Separate consumer tests](consumer/PublicConsumerTests.cs) use only public provider and Core contracts. They cover decimal round-trip, Invalid/Unsupported no-admission, result revocation, admission close/reopen, failed duplicate admission rollback, separate session/result disposal, cancellation/retry, foreign result nodes and caller XML/schema mutation isolation. Result disposal revokes its output; closing a snapshot releases only that admission. Closing the session prevents new admissions while an undisposed result retains its separately owned data. Callers must dispose both owners.

[The pilot](workload/Program.cs) performs ten warmups and **100 measured serial assess/admit/query/dispose cycles** with one real native decimal child. It checks every computed value and records latency distribution, allocated bytes, GC counts, whole-process managed memory and weak output-root observations. [Metrics](evidence/PILOT-METRICS.json) are candidate-only: no comparable shipped baseline, no regression ratio and no owner budget. Parsing, provider guards and request/result/disposal overhead are included; compile is outside the measured window. This is an observational PF-03 subset, not the complete owner scenario or a proof of zero retention.

The pilot exposes a **release-blocking prototype allocation problem**: about **31.5 GB allocated per tiny cycle**, with median latency **1.45 seconds**. The separate [single-run phase probe](evidence/PHASE-PROBE.json) attributes about 31.506 GB to `publicDataEvaluate`, while capture/assessment and admission allocate under 1 MB each. This localizes the expensive boundary, not the underlying cause. Zero observed weak roots after forced GC does not make this allocation volume acceptable. Investigate before owner-scale measurements or package preparation.


[Workload readiness](WORKLOAD-READINESS.json) keeps **all nine PF budgets and acceptance slots open**. The pilot does not qualify XmlDb/Braid, general typed lists/unions/construction, persistent storage, concurrency or large-scale behavior. The copied native adapter and strict request logic match TA-48 exactly; its 59 controls remain sealed historical evidence and were not rerun or summed with these ten consumer cases.
