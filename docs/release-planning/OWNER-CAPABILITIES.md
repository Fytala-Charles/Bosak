## Finite public contract decisions for R2

1. **Ordinary source/lifetime admission:** support untyped XmlDb without a fabricated schema assessment; optional assessment remains explicit. Select the smallest neutral lifetime capability and actual node membership route.
2. **Authority and facts:** finalize component/universe identity, derivation/affiliation/closure, original node PSVI and assessment/advisor consultation. Cover Schema N1–N8, not just the decimal profile.
3. **Value representation:** decide exact integers/decimals, narrowing/error behavior, atomic/list/union transport and constructor provenance. The six proposed numeric members and isolated prototype remain proposals until production integration is selected and tested.
4. **Compatibility and ownership:** select compatible-view proofs preserving original PSVI, supported deferred/container scopes, and actual provider concurrency/cleanup guarantees. Keep engine operation ownership separate from store/worker ownership.
5. **All-host surface and limits:** reconcile the proposed XPath/XQuery/XSLT signatures with the now-qualified private execution paths and source-free/distinct-input profiles. Resolve workload-driven limits and any broader Braid invocation requirement before accepting stable signatures.

R2 must record a disposition for each declaration in the [45-type proposal](../foundation-c45-revised-shape/README.md), its [six numeric member intents](../foundation-c45-revised-shape/NUMERIC-MEMBERS.json), and every owner requirement row. “Unsupported for this backend/profile” can be an explicit implementation outcome; silently omitting a known required future signature cannot close the freeze gate. No blanket adoption of the proposal is implied.

## Owner actions versus Core actions

Core owns R2's decision ledger and R3's accepted public implementation. Schema supplies authentic provider facts, supported/refused coverage and representative tests. XmlDb supplies actual reader/generation release, failure and concurrency evidence against the selected candidate. Braid supplies worker/invocation/currentness requirements and integration evidence. Fixtures and owner implementation can proceed in parallel where they do not depend on an unselected signature. Existing delegated work remains delegated; this audit changes no external files or requests and sends no owner messages.

Full XSD 1.1 backend completion is a separate Schema lane. The foundation release requires all known API needs to be represented and representative supported behavior qualified, with honest refusal scope; it does not require every backend feature to be finished first.
