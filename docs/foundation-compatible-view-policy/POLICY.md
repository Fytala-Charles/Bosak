# Compatible atomic identity: selected implementation boundary

5 November 2026. Selection only, source/binaries remain 1.66.0. This is not a public activation or an accepted signature delta. Original TA-20 qualification and owner design returns are preserved.

## Authenticated entry is the first gap

Current OpenSnapshot accepts caller-supplied input/lifetime/origin/view parameters but returns Unsupported for every non-null compatibilityView. A view's Source/Target/ExecutionEnvironment properties describe its claim; those getters cannot prove that a selected provider issued it. Neither equal names/fingerprints, source digests, independent schema compilation nor a view implementing the interface supplies that authority. Current source snapshot TypedAdmission stores issuer/input/origin, not a reusable public binding capability. The one-provider TA-19 call scope deliberately rejects a second advisor identity.

Select an engine-issued handoff from an existing original source SchemaQuerySnapshot. Do not activate the existing raw-view parameter or expose a factory accepting arbitrary views. Reserve exact trimmed `$compatible` with an explicit target assessor and distinct `bosak-compatible-atomic-identity-v1` / `bosak-compatible-atomic-identity-descriptor-v1`, inactive. Run/RunAsync in this profile selects exactly one target-compatible snapshot per operation, with no ordinary/other-source mixture; sessions may retain multiple admissions under the unchanged snapshot bound. The first consumer is guarded singleton String/Boolean/Integer/Decimal identity, not a new type predicate, schema-element match, numeric coercion or general compatibility equivalence.

The proposed new entry/result in SIGNATURE-PROPOSAL.md are an **open API need**, not adopted declarations. In particular, using SchemaResult<SchemaQuerySnapshot> would conflate a supported Incompatible proof with Unsupported or invent a successful null snapshot. Preserve all three existing SchemaCompatibilityDecision outcomes in an API admission result. R2's historical design closure is unchanged; this new delta needs an explicit scoped disposition before public implementation/freeze. No new mandatory provider slot is selected: the exact bound target advisor must optionally implement existing ISchemaCompatibilityAuthority and IQueryOperationLifetime; the exact source advisor must support IQueryOperationLifetime too. A separate unselected broker/assessor-wide capability is not a substitute.

## Source/target and proof

Accept only an engine-created, current, original-source snapshot with a non-null owned original assessment and internally captured exact source binding. The initial profile excludes already-compatible snapshots, source-free constructor receipts and transitive chains. Source and target sessions are distinct; same-session existing typed identity remains its own route. Foreign/missing/stale source evidence refuses before facts or container getters. The target does not reassess the source or rewrite original PSVI.

Invoke Establish only on that exact bound target advisor's optional authority, passing the engine-captured source advisor, target advisor and actual target semantic environment. It returns the current-call issuance witness. Validate the returned decision under guards; never use caller-supplied result/view objects. Compatible requires a non-null view with the exact endpoint/environment references. Non-compatible decisions must not read View or Diagnostics; use bounded fixed engine diagnostics. Null/unknown results, Compatible-null and changed endpoints are malformed. Incompatible and Unsupported remain distinct outcomes; neither opens a snapshot.

A positive admission records the original source lineage and endpoint metadata, not persistent proof authority. Each subsequent raw target operation obtains its own fresh real source/target admissions and re-establishes compatibility before source typed-value/evidence use. A later Incompatible/Unsupported result refuses before delivery. Returned views are private raw-operation witnesses only, covered by provider immutability/currentness under those admissions. No retained arbitrary view is authenticated by self-description or a hidden global registry. Independent per-view revocation and persistent proof needs remain open before broader freeze.

## Lifetime prerequisite

Implement the private bounded two-advisor call/cleanup scope first, before adding public entry or activating `$compatible`. Immutable membership is engine-selected: exact source and target advisor objects, deduplicated by reference; the compatibility authority is the target object, not a third unselected resource. At most two real admissions are acquired in deterministic source-then-target order, rolled back in reverse; the same object acquires once. No fabricated no-op admissions. The existing constructor's single-provider membership rule remains unchanged.

One serialized provider-touching call window spans both endpoints, binding checks, Establish, view/evidence/iterator callbacks and mandatory cleanup. Refuse overlap/reentry; never call a provider under an engine state lock. Track actual acquisition/call tails after callback closure, reject delivery/new work immediately, and retain raw session/source-snapshot resources until actual provider calls and cleanup end. Close/cancellation revokes both endpoints' guarded work. Canceling a wait never releases actual work. Preserve original primary and every cleanup exception object, order and aggregate boundary; release each successful admission once. Test actual independently owned file/stream resources, not just counters.

The target snapshot retains a real source snapshot lifetime obligation, without transferring the host's resource ownership. Source session/snapshot close revokes use; target close denies new work. Existing target raw work still retains original actual resources through its tail and cleanup. Drain observes the complete work and all releases. Admission/close races and failed second acquisition must leave neither an orphan source retainer nor an incorrectly admitted target snapshot. First prove these mechanics internally (MC01-MC16). No extra owner response is required to start that internal prerequisite; public signature adoption and actual native ownership remain separate.

## Original evidence and limits

The source advisor continues to authenticate original input/origin/container tuples. Source authority continues to own governing/declared/actual handles. An internal target-environment issuer adapter may exist only behind the engine's exact current compatibility witness; merely returning a target fingerprint is never authority. Preserve original assessment and member types, exact representation and container/ordinal identity. The target provider's proof admits this finite profile; do not relabel handles with target authority, manufacture target assessment or use numeric derivation as union membership evidence.

The target compatible snapshot is one target engine admission over the same actual source; MaxOpenSnapshots and MaxCachedValuesPerSnapshot retain their existing units. Per-result atom and numeric representation bounds remain unchanged. Register transactionally in that admitted target snapshot, without mutating the original source's facts/registry or sharing source/target receipts. Admission failure reserves no permanent slot. No cross-process/live authority serialization, transitive compatibility cache, deep detachment or aggregate byte/time/parse budget is promised.

## Deliberate exclusions and next work

General predicates/declaration matching, all atomic/list/union forms, compatible numeric computation, compatible node traversal/atomization, constructor import, transitive/multiple source views, XQuery/XSLT/all-host routing, persistent proof authentication and real native/owner workloads are unselected. Keep raw OpenSnapshot(..., compatibilityView) Unsupported even after the new entry is implemented; passing a copied or unissued provider view must never bypass the handoff.

Current law is the host policy preserving original provenance in the accepted R2 ledger and PL-08. The dated XDM 3.1 REC 21 March 2017 sections 2.7.1/2.7.4 already recorded by TA-18 distinguish component/type representation; they do not prescribe this compatibility proof or resource machinery. This step adopts no new language semantics. Re-record the exact immutable semantic subset and dirty source pins before implementation, and record the public delta disposition before adding it. Full XSD 1.1/native conformance and owner/freeze acceptance remain separate.
