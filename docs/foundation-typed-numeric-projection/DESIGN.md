# Authorization before computation

The internal operation requires an explicitly selected member snapshot and the exact registered transport representation. TA-03 validation rechecks the current issuer/input/container, governing/declared/actual handles, original origin, raw lifetime/cancellation and supplied atom/numeric limits before type-family authorization. Stale or forged evidence cannot become an unmarked arithmetic input through this helper.

The reader resolves `{http://www.w3.org/2001/XMLSchema}integer` through the captured selected authority, then verifies ownership of the returned component. Actual atomic type membership is checked before and after IsSameComponent and, when sameness is Supported false, IsDerivedFrom. Only Supported true authorizes a family; unsupported, absent, invalid or malformed responses refuse without reading unavailable Value. If both integer relations are Supported false, Core performs the same sequence for decimal. Authoritative semantic sameness can succeed for distinct handle references; reference interning and a handle's own Authority property are never used to establish it.

Classification uses the selected actual atomic type, not a list/union governing type or a descriptive annotation. Integer family requires an Integer payload; decimal family requires Decimal. A mathematically integral Decimal cannot silently inherit integer evidence, and a numeric-looking string or float does not become an authorized exact operand. Current coefficient/scale capacity is checked before normalization and before authority lookup. Provider callbacks and outcome Kind/Value getters run outside cache locks with current membership/resource checks around them. Actual and selected builtin ownership are rechecked through delivery.

Only after authorization does Core construct a plain Integer or exact Decimal value. This deliberately drops neither the original marker nor its metadata in place: the original cached value remains unchanged and can still follow identity transport. The projected data is computation input, not an issued schema result. Existing arithmetic limits accept it and produce plain computed primitives; the original marked input remains refused by existing plain arithmetic readers. There is no numeric result cache, extra evidence slot, new original assessment or source-free authority.

Authority lookup/relationship failures leave the existing registration intact and a valid retry can succeed. Provider exception, cancellation, close, actual/builtin revocation, foreign raw membership and escaped operations refuse. Raw resource release remains governed by the existing source lifetime; no resource is acquired or disposed by projection itself. The fixture's family labels model already-authorized provider answers; Core's classifier uses actual public authority operations rather than those labels.

The local observation uses an owned scalar inside a held raw operation, 100 warmup and 1,000 measured projections. It includes fake provider outcome allocation, current guards and plain primitive construction. It does not measure public arithmetic setup, native relation cost, aggregate retained memory or accepted PF-01–09 budgets. Public integration still needs a distinct descriptor/profile, captured limits, pre/post operand validation and guarded arithmetic execution before it is enabled.
