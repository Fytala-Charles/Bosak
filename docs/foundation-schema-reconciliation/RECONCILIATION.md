## A concrete adapter feasibility direction, not an implementation

A provider-local sealed node projection can retain its trusted input owner and node identity in private fields. Membership then checks availability, known sealed type and exact owner reference before delegating any content getter. Every node-producing route—parent/document/children/axes/attributes/virtual namespace nodes—must preserve that ownership; returning unregistered raw wrappers would lose the guarantee. Typed containers similarly need a private issued-source/origin association, checked before contents/iteration. Snapshot-specific reads remain in the Core contract.

This uses the existing IXdmNode and proposed input/advisor predicates; it does not require adding a mandatory identity getter to legacy IXdmNode. It needs an actual owner design/implementation review: no such adapter was built or qualified in this step. Initial assessment/export copying is distinct from eagerly copying a graph merely to authenticate admission. A provider can retain its private immutable export and authenticate identities without using the legacy content-shape scan as its membership predicate.

The public XdmElementAssessment carrier is a **trusted-host annotation bridge**, not an authentication boundary. Its factory can attach the same owner/state references to a different element; the executable control demonstrates this without changing the original assessment. Checking carrier Owner/State, GUIDs or content alone therefore cannot establish BCAP source membership. Authentic association must come from the provider's actual admitted graph and issued objects. This is not a newly discovered shipping security defect; the bridge documents trusted-host attachment and no validation/authority issuance.
