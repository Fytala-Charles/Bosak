# Transaction boundary and lifetime

Each admitted snapshot lazily selects a scalar registry bound to the exact snapshot/environment, selected issuer, original public input and authority. A managed atomic mode latch excludes the older private association in either ordering, including racing selection. Rejected internally constructed legacy associations are cleaned up by their caller. Ordinary admissions allocate no additional cache lock unless this internal route is used.

Keys use container/origin references and ordinal position. Hashing uses runtime reference identity; provider Equals/GetHashCode never runs. Nonempty groups retain governing type, list shape and ordered declared/actual/origin/payload cells through their scalar entries. There is no independent container dictionary, empty-container record, label-based interning or eviction. Originless reads still require a real admitted snapshot. MaxTypedValueAtoms bounds each result independently from the resident scalar ceiling; neither is a total byte budget.

Cold preparation uses the qualified TA-01 reader and stages immutable cells, identities and the delivery object before publication. Warm preparation revalidates issuer/container/component ownership and supplied numeric/result limits without replaying payload/provenance getters. The selected issuer must attest immutable/version-guarded contents while membership remains valid. Resident groups retain no checker or raw-operation lease from the creating call; each delivery uses its current raw operation.

Provider checks run outside the registry lock. Inside it, Core checks managed raw/session/snapshot lifetime, cancellation, concurrent winners and wide capacity arithmetic, ensures only actual required dictionary capacity, then installs the complete group. A fixed integer insertion-fault seam invokes no callback. On precommit failure, recomputed value-type keys remove only the inserted prefix without allocating undo storage; prior entries remain unchanged. Dictionary bucket capacity may remain grown. This does not claim recovery from every process-fatal or allocator failure.

Completed installation is the commit point. Cancellation, revocation or delivery failure afterward can leave a complete reusable batch. Source close clears the registry; no cache entry owns or disposes borrowed provider resources. The original source/raw-operation lifetime controls actual release and drain. Guarded container/atomic views expire with the delivering raw operation, even when a later operation reuses the same resident identities. A returned internal identity is not an authenticated VM transport marker or a lease.

Actual concurrent raw operations cover duplicate-winner reuse and distinct-batch capacity races. Close/cancel tests distinguish staging, commit and delivery. Actual temporary FileStream ownership survives logical close until raw completion; a throwing owner cleanup preserves primary/cleanup ordering and faulted drain. Local observations cover cold scalar registration, a warm three-cell list and caught capacity refusal after runtime warmup. They do not establish representative owner budgets or aggregate retained-memory limits.

Public schema Unsupported guards and ordinary/numeric v1-v5 profiles remain unchanged. Private transport attachment, the public adapter, typed numeric projection and wider host/provider acceptance require later slices.
